## 服务与进程

**健康检查先判死活**：规范端点 `GET /health`（`/api/health` 是兼容别名），返回 `{"project":"珞珈智行","status":"ok","timestamp":...}`。线上 `curl https://whuspati.online/health`；本机 `curl http://localhost:5000/health`。

**线上 502 Bad Gateway**：Caddy 正常但 gunicorn 没起来。看日志：

```bash
sudo systemctl status whu-walker
sudo journalctl -u whu-walker -n 100 --no-pager
```

常见原因：

- gunicorn 参数被改动。必须且只能用 `--workers 2 --threads 4 --timeout 60 --max-requests 1000 --bind 127.0.0.1:5000`；加 `--preload`（全局对象多 worker 冲突）、`--keepalive`、`--max-requests-jitter`（现版本不识别）都会启动失败。
- `.env` 缺关键变量或 YAML/JSON 语法问题导致 import 失败；本机先用 `venv/bin/python -c "import app"` 验证能导入。
- 5000 端口被占：`ss -ltnp | grep 5000`。

**请求体过大被拒**：生产模式 `MAX_CONTENT_LENGTH=1MB`，超大 POST 直接 413，属预期保护。

**更新后未生效**：服务器 `origin` 是 Gitee，更新流程是 `git fetch origin && git reset --hard origin/main && sudo systemctl restart whu-walker`；推到 GitHub 镜像不会上线。

**Caddy 证书异常**：确认域名 A 记录指向 152.136.102.172、80/443 已放行，`sudo systemctl reload caddy` 后看 `journalctl -u caddy`。

## LLM 与 Agent

**DeepSeek 不可用时用户侧表现**：不是报错，而是静默降级。`agents/planner.py` 遇到断网/鉴权失败等抛 `PlannerError`，由 `api/routes.py` 的 `chat()` 捕获后落回旧 parser 规则管道（意图分类 + 模板解释）。若线上回答突然变短、不会多轮追问、工具能力消失，先查服务日志里的 fallback 记录，再核对 `DEEPSEEK_API_KEY` 与 `OPENAI_BASE_URL`、额度与网络出网。

**规划超时 / 回答慢**：Agent 预算为 `MAX_TURNS=6`、`TIME_BUDGET_S=40.0`、`LLM_MAX_TOKENS=800`，到点强制收尾；gunicorn `--timeout 60` 是外层上限，不要随意调大其中一个而不调另一个。慢查询优先看是 LLM 首 token 慢还是路网首次加载（冷启动）。

**出行方式被误判**：关键词检测在 `agents/parser.py` 的 `detect_travel_mode()`，顺序 bike → drive → walk；单字「车」不参与匹配（避免「停车场」「校车」误触发），必须是「骑车/开车/自驾/打车」等词。前端方式按钮显式传入的 `travel_mode` 会注入 Agent 上下文（planner 内白名单当前仅 walk/bike/drive，新增方式要同步）。

**温度（确定性）**：planner 与 parser 均为 `temperature=0.0`；explainer 各生成函数温度不同（0.3–0.6）。排查「每次回答不一致」时先确认分歧出在规划还是解释环节。

## 地图与坐标

**底图灰屏 / `INVALID_USER_KEY` / `USERKEY_PLAT_NOMATCH`**：`AMAP_KEY` 或 `AMAP_SECURITY_CODE` 未配置/不配套；线上还需在高德控制台把 `whuspati.online` 加入 JS API 2.0 域名白名单（本地开发加 localhost）。

**路线整体偏移约 50–500 米**：几乎都是坐标系问题。全站底图与 POI 统一 **GCJ-02**，OSM 路网是 **WGS-84**，入口须 `gcj02_to_wgs84()`、出口须 `wgs84_to_gcj02()`（见 `spatial/coord_transform.py`）。前端禁止改接 OSM/Esri/天地图 `vec_w` 等 WGS-84 瓦片源（app.js 中有明确约束注释），换源即偏约 500m。GPS 原生坐标（WGS-84）走起终点 `type="coord"`，后端会转换，不要在前端先转成 GCJ。

**天气卡片失败**：天气走高德接口，同样受 Key 与域名白名单限制；失败不阻塞路线结果。

## 路径、POI 与路况

**提示找不到可达路线**：按顺序排查——

1. 路况硬封：封闭事件会从方式图删边；全部方式都受影响（步行也绕封路）。若硬封导致不可达，会软降级重试（封闭边 1000× 成本），响应 `filter_status` 含 `degraded_road_closure`；仍不可达才提示。可临时结束/删除路况事件验证。
2. 方式过滤过激：骑行/驾车剔除台阶与非车行路（`_NON_VEHICULAR_HIGHWAY`、`_DRIVE_ALLOWED_HIGHWAY`），极端情况下过滤后图为空会自动回退原图并在 `filter_status` 带 `degraded` 标记。
3. `data/edge_overrides.json` 人工封禁：`blocked_modes` 硬封禁、`walk_penalty` 软惩罚，检查是否误封必经边。

**路线穿到校外市政路**：步行有校外距离惩罚（10×），骑行 3×、驾车 1.2×（`MODE_OUTSIDE_ROAD_PENALTY`）；路网本身经校园多边形 +约 120m 缓冲裁剪。仍穿城时检查 `clip_to_campus.py` 的校外道路黑名单是否漏了新路段。

**POI 名称识别不到**：

- 先确认是不是别名：樱顶（=武汉大学老斋舍）、教五（=武汉大学第五教学楼）、行政楼（=武汉大学早期建筑工学院）、总图书馆（=武汉大学图书馆(总馆)）、牌坊等都以别名形式存在，经两阶段 POI 归一解析；`/api/candidates` 可查候选。
- 数字写法会归一：「十四舍」=「14舍」（`spatial/poi.py` 中文数字转换 + `_normalize_num`）。
- 校门条目共 **12 个**（`subcategory:"gate"`），不要凭印象写「13 个校门」。
- 数据共 420 条 POI；新增/改名后跑 `python scripts/validate/validate_all_data.py`，别名与他人正式名冲突会报错。

**路况事件「建了不生效」**：创建点经 `snap_to_edge` 吸附，超过 30m 无匹配边会失败；时间窗未开始/已过期的事件默认不出现在列表（管理员加 `?all=1` 可见）；时间支持 `2026-09-10T08:00` 这类 ISO 字符串或秒级时间戳。

**路况影响以代码矩阵为准**（`spatial/road_conditions.py` 的 `CONDITION_EFFECTS`，前端 app.js 同表；该文件 docstring 顶部旧矩阵已过时）：封闭全方式硬封；施工步行 1.5×/骑行驾车硬封；积水步行骑行硬封/驾车 1.5×；事故步行骑行 1.3×/驾车硬封；活动步行骑行 1.2×/驾车硬封。「步行不受路况影响」「事故一律 3×」都是旧版错误说法。

**路况接口 401/403**：写操作（POST/PATCH/DELETE、`/snap`）需要管理员身份——网页先 `POST /api/admin/login`（`ROAD_CONDITION_ADMIN_PASSWORD` 未配置时返回 403 `admin_disabled 管理员功能未配置`），或带 `X-Admin-Token` / `Authorization: Bearer`（需配 `ROAD_CONDITION_ADMIN_TOKEN`）。Token 用 hmac.compare_digest 校验，注意尾空格/换行。

## PWA 缓存

Service Worker（`static/sw.js`）策略：

| 资源 | 策略 |
|---|---|
| 页面导航（HTML） | network-first |
| 其他静态资源 `/static/*` | cache-first |
| `/api/road-conditions*`、`/api/admin*` | network-only（强一致） |
| 其他 `/api/*` | stale-while-revalidate（离线返回缓存或 504） |
| `/app/*`（APK、latest.json） | network-only（同名覆盖发版） |
| 高德等第三方 | network-only |

**改了 JS/CSS 但用户看不到**：`CACHE_NAME` 当前为 `whu-walker-v47`（版本号随发版递增，**不要在代码里写死引用它**）。凡改动 `PRECACHE_URLS` 列出的预缓存文件，必须把版本号 +1，activate 阶段才会清掉旧缓存；仅改非预缓存静态文件时配合 index.html 的 `?v=` 查询串失效。排查时可在浏览器 DevTools → Application → Service Workers → Update now，或 Clear storage 后强刷。

## APK 与语音

**不弹更新提示**：客户端只比较 `latest.json` 的整数 `versionCode`（当前 6，versionName 1.4.1），versionName 字符串不参与比较；发新版必须两者都在 `static/app/latest.json` 与 AndroidManifest 同步递增，并替换同 URL 的 APK（`/app/` 为 network-only，不会被 SW 缓存）。

**下载后不安装**：安装前做 SHA-256 校验，APK 实际哈希与 `latest.json` 的 `sha256` 不一致会拒绝安装——重新出包后必须同步更新清单；首次安装还需用户授予「安装未知应用」权限（`REQUEST_INSTALL_PACKAGES`）。

**语音输入不可用**：App 枚举系统 `RecognitionService`；设备无可用语音引擎时提示「这台设备没有可用的语音识别服务，请直接打字，或在系统设置里启用语音引擎」。Android 11+ 需在 Manifest 用 `<queries>` 声明 `android.speech.RecognitionService` 包可见性（已声明），定制 ROM 上仍可能缺失，属设备环境问题而非代码故障。

## 微信内置浏览器

微信内只有 UA 检测引导逻辑（无任何「备案拦截弹窗」代码，排查时不要朝这个方向找）：微信内置浏览器中语音能力受限、APK 安装常被拦截，页面检测到 MicroMessenger UA 后引导用户「点右上角 ⋯ → 在浏览器打开」完成语音输入与安装。若用户反馈二维码链接在微信里打不开，让其用系统浏览器扫码/打开即可（`scripts/gen_qrcode.py` 生成 `static/qrcode_access.png`）。

## 路网与标注

**首次加载报 osmnx 缺失**：`requirements.txt` 不含 osmnx（运行时靠 graphml 缓存）；缓存缺失需要重新下载时，安装 `requirements-dev.txt`，或手工把 `data/whu_road_network.graphml` 放到对应位置。生产模式启动有后台预热线程，预热失败只告警不阻断启动，此时首次规划会变慢。

**强制重建**：`python scripts/network/rebuild_network.py`（删缓存按 `WHU_BBOX_*` 重下），或 `POST /api/network/init` 带 `{"force": true}`。重建后注意：路况事件靠边链几何回退（12m 容差）自动恢复；但 `edge_overrides.json` 按 (u,v,key) 绑定，节点 id 全变后必须重跑 `scripts/audit_network.py` + `scripts/build_edge_overrides.py`。

**标注覆盖率告警**：路段坡度/景观标注覆盖率低于 80% 时进入降级模式，未标注路段仅按距离成本计；用 `python scripts/validate/T026_validate_annotations.py` 查看覆盖率与降级标记，补标后重启服务。

## 测试与自检

- 测试基线 **373 collected**：`python -m pytest tests/`。数量对不上先确认是否漏拉最新代码或本地有新增/跳过的用例。
- 需要运行中服务的用例带 `e2e` marker（`test_end_to_end.py`、`test_multiturn.py`），不起服务时它们被跳过；显式跳过用 `python -m pytest tests/ -m "not e2e"`。
- `scripts/validate/qa_smoke.py` 是 Playwright 冒烟，需先 `pip install playwright && playwright install chromium` 并自行启动 Flask（脚本不会帮你起服务）。
- 历史任务自检脚本（T005/T010/T018/T022/T026、validate_sla 等）均可离线静态运行，适合发版前快速回归，覆盖内容见 [08_开发指南](08_开发指南.md)。
