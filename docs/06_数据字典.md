# 06 · 数据字典

所有生产数据在 `data/` 目录，JSON/GraphML 文本格式，启动时加载到内存，无数据库。

## 文件总览

| 文件 | 内容 | 写入方式 |
|---|---|---|
| `pois.json` | 420 个 POI 主数据 | 离线构建，随版本发布 |
| `road_annotations.json` | 12,550 条路网边的坡度/景观标注（含 DEM 反算） | 离线构建 |
| `edge_overrides.json` | 208 条人工路网覆盖（穿楼封禁、食堂区软惩罚等） | `scripts/build_edge_overrides.py` 生成 + 人工校对 |
| `task_cards.json` | 9 张校园场景经验卡（Agent 静态记忆） | 人工维护 |
| `road_conditions.json` | 实时路况事件 | 运行时由管理员接口写入 |
| `user_profiles.json` | 用户 EMA 偏好画像 | 运行时由 telemetry 写入（文件锁） |
| `telemetry.jsonl` | 行为埋点（route_shown/route_accept） | 运行时追加 |
| `whu_road_network.graphml` | 裁剪后的 OSM 路网缓存（约 4.6MB，不入 git） | 首次运行下载，`scripts/network/` 脚本重建 |

## POI（pois.json）

结构：`{"pois": [...]}`，每条：

```json
{
  "id": "poi_140",
  "name": "珞珈门",
  "aliases": ["牌坊", "主入口", "八一路牌坊"],
  "coordinates": {"lng": 114.358238, "lat": 30.53334},
  "type": "gate",
  "subcategory": "gate",
  "category": "gate",
  "campus": "文理学部",
  "description": "武大正门八一路老牌坊……",
  "scenery_score": 1,
  "rating": null,
  "season_tags": ["all"],
  "is_minor": false
}
```

| 字段 | 说明 |
|---|---|
| `id` | 唯一标识 `poi_NNN` |
| `name` | 规范名（已消歧，如同名地点按学部分化） |
| `aliases` | 别名，含中文数字归一化形式（"七舍"/"7舍"） |
| `coordinates` | `{lng, lat}`，**GCJ-02** |
| `type` | 一级类型（见下表） |
| `subcategory` | 细分类，与 Agent 工具枚举对齐（canteen/coffee/sakura/library/gym/bank/hospital…） |
| `campus` | 文理学部 / 工学部 / 信息学部（少量区域点为跨区/其他） |
| `scenery_score` | 1–5 景观/重要度评分 |
| `rating` | 高德评分，可空 |
| `season_tags` | 季节标签；多数为 `["all"]`，季节推荐主要靠 task_cards 的 season_hint |
| `is_minor` | true=小店铺（连锁奶茶/档口），游览选点等场景默认排除 |

**类型分布（420）**：dining 餐饮 127、study 教学自习 113、dorm 宿舍 101、scenery 风景 29、sports 运动 19、gate 校门 12、service 服务设施 11、area 区域 8。

**12 个校门**：珞珈门、珞瑜门、珞瑜二门、珞南门、凌波门、扬波门、北门、弘毅门、洪波门、文澜门、茶港门、科技门。

**范围硬约束**：仅文理/工学/信息三学部；含校医院、自强超市、工行、邮政、活动中心等中大型设施；排除校外地点、小商铺中的纯商业档口（以 is_minor 标记区分）、教工宿舍/家属区/私人公寓。

## 路网边标注（road_annotations.json）

```json
{
  "version": "2.0",
  "annotator": "...",
  "annotated_at": "...",
  "coverage": ...,
  "coverage_rate": ...,
  "slope_source": "dem|placeholder",
  "edges": [
    {
      "edge_id": [286074435, 1358787402, 0],
      "u": 286074435, "v": 1358787402,
      "name": "东湖南路",
      "length_m": 76.0,
      "highway": "tertiary",
      "slope_level": 2,
      "scenery_level": 4,
      "note": "坡度占位，待实测; 临近 扬波门 (43m)"
    }
  ]
}
```

- 共 **12,550 条边**（与裁剪后 graphml 对齐）；`slope_level` / `scenery_level` 均 1–5（1 平坦/景观一般，5 陡/景观最好）。
- 坡度来源：长度 ≥50m 的主干道经 `scripts/network/compute_slope_from_dem.py` 从 open-elevation（SRTM/ASTER 30m）反算（节点高程中位数平滑）；短边与无数据边保留占位等级（默认 3），`note` 中注明。
- 合并策略（DEC-017）：优先 `edge_id [u,v,k]` 精确匹配，回退 u/v 节点对；匹配失败静默跳过。
- `geometry` 等完整拓扑在 graphml，不在本文件。

## 人工路网覆盖（edge_overrides.json）

`scripts/build_edge_overrides.py` 用 OSM 建筑轮廓相交检测生成，命名道路不自动封禁：

```json
{
  "_comment": "……",
  "edges": [
    {"u": 1146763175, "v": 1408369118, "k": 0,
     "walk_penalty": 10.0, "blocked_modes": ["bike", "drive"],
     "reason": "crosses_building", "name_hint": "未命名路 …"}
  ]
}
```

- `blocked_modes`：硬封禁模式（如穿越建筑的边禁骑行/驾车；台阶禁 bike/drive 也在该体系内）；
- `walk_penalty`：步行软惩罚倍数（台阶 2.5×；食堂区域 10 条有向边 10× 防穿楼）。

## 任务卡（task_cards.json）

Agent 静态记忆，结构：

```json
{
  "id": "sakura_viewing",
  "name": "赏樱",
  "triggers": ["樱花", "赏樱", "看花", "樱花大道", "樱顶"],
  "season_hint": "spring",
  "applies_to": ["plan_tour", "search_poi_candidates", "plan_route"],
  "advice": "赏樱首选 subcategory=sakura 的地点……",
  "default_weights": {"distance": 0.15, "slope": 0.15, "scenery": 0.7}
}
```

召回规则：query 命中 triggers 数排序、季节匹配 +1，每轮最多注入 2 张。新增卡片只需追加，无需改代码。

## 路况事件（road_conditions.json）

运行时数据，初始为 `[]`。事件结构（`spatial/road_conditions.py`）：

```json
{
  "id": "rc_...",
  "type": "construction",
  "name": "樱花大道施工",
  "description": "...",
  "edge": {"edge_id": [u, v, k], "road_name": "...", "chain": [[u,v,k], ...]},
  "click_point": {"lng": 0, "lat": 0},
  "start_time": 0,
  "end_time": 1789000000,
  "created_by": "web|token",
  "created_at": 0
}
```

- type ∈ closure/construction/flooding/accident/event；生效矩阵见 [05_架构设计](05_架构设计.md#路况全出行方式生效)。
- `edge` 为服务端吸附结果（点击点 30m 内）并沿拓扑扩展成路口间边链 `chain`；节点 id 失效时用几何 12m 容差回退。
- `start_time/end_time` 为 Unix 秒，0 表示"立即/长期"。

## 用户画像（user_profiles.json）

```json
{"whu_uid_xxx": {
  "weights": {"distance": 0.8, "slope": 0.05, "scenery": 0.15},
  "accepted_count": 5,
  "exposure_count": 9
}}
```

EMA α=0.3，仅 route_accept 更新；accepted_count ≥ 3 才注入 Agent 上下文。

## 坐标系

| 数据 | 坐标系 |
|---|---|
| pois.json、路况点击点、前端一切展示 | GCJ-02 |
| graphml 路网、DEM、图计算过程 | WGS-84 |
| /api/chat 入参 coord_start/coord_end/waypoints | WGS-84（GPS 原生） |

API 边界负责双向转换，数据文件本身不要混入另一坐标系的坐标。

## 数据源与构建

- **POI**：高德 Web 服务（place/around/regeo）+ OSM + 人工核对，脚本在 `scripts/fetch/` 与 `scripts/tag_subcategory.py`。
- **路网**：OSMnx `network_type="walk"` 下载 → `scripts/network/clip_to_campus.py` 按校园多边形裁剪（外扩 120m 保留校门过街）→ GraphML 缓存。
- **坡度**：SRTM/ASTER DEM 反算（compute_slope_from_dem.py），景观等级人工标注。
- **校验**：`python scripts/validate/validate_all_data.py`（字段/坐标/类型/校区归属/重名/别名冲突）、`verify_poi_coords.py`（锚点距离核验）。

## 已知限制

- 短边（<50m）坡度多为占位值；个别校区交界地带归属存在固有模糊。
- 部分 POI 无高德评分（rating=null）；季节标签大多数为 all，细粒度季节感知依赖任务卡而非 POI 标签。
- 画像 JSON 多 worker 下可能丢更新（软先验，可容忍）。
