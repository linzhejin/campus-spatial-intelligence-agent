# 视觉图像识别功能实施与验收（2026-10-03）

## 目标与结论

本轮先调研、再实现并部署管理员使用的航拍影像识别：识别车辆，给出单图车辆密集观察提示；视频经过相机运动补偿后，满足保守门槛时生成“可能存在拥堵”的人工核验候选。该功能不属于自动交通执法或自动路网管制。

可用公开数据尚不能支持武大现场精度或事故识别的承诺。因此选用 VisDrone2019-DET 上的公开车辆检测模型作为研究原型，保留模型许可、版本和校验和；事故识别明确不支持。模型卡数据只是原数据集基准，不代表武大环境效果。

## 方案与实现

- **模型与运行：** `dronefreak/visdrone-rtdetrv4-s` 固定模型版本 `820fca3d962243f7d611dd35cf2a64d267635499`，固定导出代码版本 `be440e87ca85927404e739c2dee17c502cd09939`。模型转换为自包含 ONNX，在 CPU 上通过 ONNX Runtime 推理；服务器不安装 PyTorch 或 Ultralytics。置信度阈值 `0.369` 是模型卡在 VisDrone 测试集报告的 F1 最优点，不是本项目调优后的阈值。
- **任务隔离：** Web/Agent 与影像推理在独立进程中运行；worker 单任务处理、1 个 CPU 线程、CPU 75% 和内存 768 MiB 上限。管理员界面仅在模型文件、依赖和 worker 心跳都正常时开放提交。
- **图像结果：** 管理台展示车辆检测框、类别、置信度和模型版本。服务端将像素框裁回原图坐标；框不转换为经纬度。
- **视频线索：** 以 ORB/RANSAC 估算相邻帧背景单应变换并校正相机运动，再关联车辆轨迹。少于 5 帧、运动补偿不足或证据不充分时不生成拥堵候选。候选需要管理员人工查看原片及现场位置。
- **安全边界：** 所有影像端点继续要求管理员身份；审核动作只确认或驳回候选，不直接创建道路管制，不改变 Agent 路线结果。

## 适用范围与限制

1. VisDrone 模型识别 11 类航拍目标，包含车辆类别，不包含事故类别；当前不报告事故候选。若论文要研究事故识别，需先获得有明确使用许可、含事故标注的数据和专用模型，再单独验收。
2. 单张静态图只能观察车辆数量/分布，无法证明车辆速度和拥堵。视频拥堵判断仍是规则候选，受镜头运动估计、拍摄角度、遮挡和抽样帧率影响；不应描述成已验证的武大实时拥堵监测。
3. 管理员选点只标记影像观察区域；检测框是原图像素坐标。本轮没有机载相机内外参数、视频位姿或正射影像，因此不能从框定位到具体道路。
4. VisDrone 数据及该模型使用 CC BY-NC-SA 3.0 非商业研究许可。模型权重不随仓库或前端分发。若用途改变为商业，需先取得另行授权。
5. 下一阶段论文评测只需先建立少量分层、经允许的武大图像/视频核验样本，评估车辆框和人工拥堵候选一致性；不需要遍历测量全校道路。
