# 移动端交互与定位可靠性实施计划

> 本文是设计和实施过程记录，不代表最新线上验收结论。当前快照见 [2026-10-01 项目进度与基础评测](18_项目进度与基础评测_20261001.md)。

更新日期：2026-09-30

## 目标

在不改动现有路线决策、会话状态和定位权限边界的前提下，解决手机上长对话回看困难、路线反馈冗长、地图选点控件难用，以及缓存位置导致实时 GPS 不重新居中的问题。定位远离武大校园时保留校园地图视野并给用户明确提示。

## 设计决定

1. 手机地图与聊天区继续采用现有约 55/45 初始分屏；聊天区顶部增加可拖动分隔柄。拖动只修改面板尺寸，不触发路线、出行方式或对话状态变化。限制地图区约 28%–76% 屏幕高度并为聊天保留约 240px；支持触摸、鼠标、方向键、焦点和读屏语义。旋转屏幕后尺寸收敛到可用范围，不跨会话保存。
2. 地图右上角起点、途经、终点重做为真正的按钮，使用珞珈朱红、松绿、暖橙的统一视觉、明确选中态、至少 44px 触控高度与可见键盘焦点。路线偏好和出行方式的快捷按钮统一尺寸、对比度、间距和按压状态；保留现有文案与点击行为。
3. 用户发出新消息时跟随到最新内容；后续模型回复、路线卡和澄清项只在用户原本靠近底部时自动跟随，避免阅读历史时被强制拉回末尾。
4. 对话路线说明由“逐项重复路线字段”改为短句优先级：用户明确偏好/约束、必要的路线退化提示、最多一条关键途经信息。距离、耗时等结构化信息仍由摘要卡显示。约 90 个汉字目标，不用截断破坏句意的方式控长。
5. 上次位置可以作为临时蓝点显示，但不再影响地图视野，也不消耗本页面首次实时定位机会。首次新鲜 GPS 只有在武大校园中心约 3km 范围内才居中到定位点；范围外保留当前武大视野，显示“当前位置不在武大校园附近，已保留校园地图”提示。若用户在等待 GPS 时已主动拖动、缩放或操作地图，迟到的首次 GPS 不再抢镜头；手动地图选点和显式重置仍按用户指令操作。GPS 数据流、marker 与导航订阅保持工作。
6. 用一套真实移动视口回归覆盖分隔柄尺寸变化、聊天滚动、按钮选中态、缓存到实时 GPS 更新、校内/校外定位视野。完整运行项目现有测试、代码审查，再提交到生产使用的 Gitee 主线并部署 Web 与已配置的 worker；部署后验证健康检查和静态资源缓存版本。

## 实施顺序

1. 增加定位中心决策与前端交互的回归检查，复现缓存位置抢占首次居中的旧行为。
2. 实现可拖分屏、按钮设计和精简解释。
3. 修复首次定位状态机并加校园距离判断和校外提示。
4. 升级 HTML 与 Service Worker 静态缓存版本，验证桌面/手机视口和全量自动化测试。
5. 请独立代码审查检查本轮 UI/定位改动及现有 Agent 平台交付；修复审查发现的问题。
6. 提交到部署用 Gitee 主线，确认生产 Web、Agent worker 与数据库配置状态后部署，做上线健康检查和手机静态资源版本检查。

## 验收标准

- 手机对话/地图初始比例与当前一致；拖动分隔柄后地图尺寸、聊天可视高度同步变化；消息内容仍可独立滚动；桌面布局不受影响。
- 起点、途经、终点均为可聚焦、可触控按钮，选中态清晰；快捷键不会触发非预期状态变更。
- 路线解释短而可读，仍保留真实偏好和必要的限制放宽说明。
- 缓存位置显示时地图保持校园中心；首次实时 GPS 在校园附近时地图居中一次；远距离 GPS 不挪动校园视野并显示提示。
- 不回归项目现有全量测试；移动端浏览器验收和生产健康检查通过。

## 交付记录

### 实施与验证

- 已完成移动端地图/对话分隔拖动、长对话按用户阅读位置跟随、路线说明精简、地图选点控件改版，以及缓存定位与实时定位分离、远距离定位保留武大视野等改动。
- `python -m pytest -q`：**697 passed / 47 skipped / 1 xfailed**。跳过项主要要求 PostgreSQL 与可选视觉运行条件；它们不能证明线上 PostgreSQL worker 已就绪。
- `npm run test:js`：**55 passed**；语法检查、Python `compileall`、`git diff --check` 均通过。
- Edge 移动视口实测：390×844 下地图初始高度 464px（约 55%），拖动后 354px；历史对话区可独立滚动；选点按钮高 44px、选中态为高对比配色；桌面视口不显示移动分隔柄。
- 定位状态机由 JavaScript 回归覆盖：缓存位置不抢占首个实时定位，校内实时位置可居中，校外首个实时位置保留武大视野并给出提示，之后进入校园仍可聚焦。
- 独立代码审查发现并已修复并行澄清乱序覆盖、用户手动地图操作被迟到 GPS 抢镜头、Service Worker 预缓存失败仍接管、Flask 上传限额 API 版本下限不符，以及部署未安装 Agent worker 等问题；新增回归用例，并让 worker 明确读取项目 `.env`。
- 发布脚本现会校验随机 `SECRET_KEY` 和 PostgreSQL `DATABASE_URL`，先连接并执行迁移，再安装/启动 Agent systemd worker；部署指南补充了单机 PostgreSQL 与现有服务器 worker unit 的操作说明。视觉可选依赖应安装在 Web 共用的虚拟环境，推理由独立进程执行，以匹配管理台 readiness 检查。

### 生产部署阻塞

- 生产 Web 当前仍在运行且 `/health` 返回正常，但服务器没有 PostgreSQL 服务、没有 `DATABASE_URL`，也没有 Agent worker systemd 服务。新会话前端已经改为调用持久化会话与异步 run API；不先配置数据库和 worker 就发布会导致新对话无法建立或任务一直停在队列，故不得将其作为已完成上线。
- 服务器 `ubuntu` 账号当前没有免密 sudo 权限；远程执行只读核查可用，但无法安装 PostgreSQL、创建系统级 worker unit 或重启 Web 服务。
- 数据库完成配置并与 Web 共用同一连接串后，需要启动 Agent worker，再部署应用、执行迁移，并在线验证一次真实会话/任务闭环。视觉推理还需要另行安装可选依赖并提供经过授权和核验的本地模型；目前不宣称机载影像识别已可用于真实监管。
