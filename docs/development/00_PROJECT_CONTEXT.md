# 00_PROJECT_CONTEXT.md — 项目上下文

## 1. 项目名称

**漫步珞珈 (WHU-Walker)**
一个轻松的个人 Demo：用自然语言跟地图对话，让 LLM 帮你逛武大

## 2. 一句话描述

探索大语言模型是否能够通过 Agent 架构调用 GIS 工具，实现自然语言驱动的空间认知与空间决策。

## 3. 项目背景

- 大语言模型（LLM）已具备较强的自然语言理解和任务规划能力，但主要处理文本信息。
- 传统 LLM 对于具有空间关系、地理约束和环境因素的问题缺乏直接理解能力。
- 例如"帮我规划一条好走的路线，沿途多看看风景，不想爬坡"——这类任务需要综合考虑道路网络、空间距离、地形坡度、景观价值、个人偏好等多维因素。
- 目前，完成此类空间分析任务需要用户掌握 GIS 操作技能，存在较高的使用门槛。

## 4. 目标用户

所有想在武大校园内找路、逛景点的人。不预设用户身份（老人/游客/学生），用户直接通过自然语言描述自己的偏好和约束。

## 5. 要解决的问题

1. **自然语言到空间约束的直接转换**：LLM 能否从"我想慢慢逛、不想爬坡、多看风景"这类自然语言中，直接提取出可计算的空间约束（坡度低、景观值高、距离不限），而不需要通过"用户画像"这一中间层？
2. **GIS 工具的 Agent 化调用**：Agent 能否自主选择并调用合适的 GIS 分析工具（路径规划、缓冲区分析、邻近查询等）？
3. **偏好驱动的空间决策**：相比仅优化距离的传统方法，引入多因素效用模型（距离 + 坡度 + 景观）是否能产生更符合用户需求的推荐结果？

## 6. 项目目标

构建一个校园尺度的空间智能 Agent 原型系统，实现：

> 自然语言需求 → 空间任务理解 → 空间约束生成 → 调用 GIS 分析工具 → 空间决策 → 地图可视化与解释

用户无需学习 GIS 操作，通过自然语言描述需求即可完成基础空间分析任务。

**范围限定（V1）**：武汉大学校园核心区域，路径规划 + 多因素成本优化为首要功能。

**交付形式**：网页应用（手机 + 桌面双端适配），公网链接可访问，支持 PWA 添加到主屏幕。

## 7. 成功指标（可量化）

| # | 指标 | 目标 | 验证方式 |
|---|---|---|---|
| 1 | 约束提取准确率 | ≥ 80%（15 条 query） | 人工判断 LLM 提取的 slope/distance/scenery 约束是否符合输入语意 |
| 2 | 路线差异化 | 多因素路径 vs 最短路径重叠率 ≤ 70% | 计算两条路线共享路段占比 |
| 3 | 路线合理性 | ≥ 3/5 人认为路线"符合预期" | 找 3-5 个同学试用 3 条 query，打分 |
| 4 | 系统稳定性 | 端到端无崩溃、无超时 | 连续跑 15 条 query，无异常退出 |
| 5 | 双端可用 | 手机地图可触摸交互，桌面布局正常 | 至少 1 台手机 + 1 台电脑测试 |
| 6 | 响应时间 | 单次查询 ≤ 15 秒 | 含 LLM 调用 + GIS 计算 + 地图渲染 |

## 8. 已知限制

- **空间范围**：仅限武汉大学校园核心区域，不覆盖城市尺度。
- **道路数据**：V1 基座数据使用 OpenStreetMap（GIS 计算层），前端地图展示使用高德 JS API。校园内部小路可能存在数据缺失。
- **高程精度**：V1 可能无法获取高精度 DEM 数据，坡度分析精度受限。
- **语言限制**：仅支持中文自然语言输入。
- **用户规模**：研究原型，不支持多用户并发。
- **后端部署**：需要 Flask 运行环境，不能纯静态托管（V1 用 Render 免费部署）。

## 9. 未确定问题

1. OSM 在武汉大学校园的道路数据覆盖率和精度是否足够支撑路径规划？【待数据验证】
2. DEM 高程数据（SRTM 30m）在校园尺度的坡度计算精度是否可用？【待验证】
3. "景观价值"如何在数据层面量化？——POI 类型？距离衰减？用户评分？【待定义】
4. LLM 对模糊地名的消歧能力——例如"樱顶"是否能正确映射到坐标？【待测试】
5. 不同约束组合（坡度/距离/景观）的权重映射是否需要文献或调研支撑？还是凭经验设定？【待调研】

## 10. 风险列表

| 风险 | 可能性 | 影响 | 缓解措施 |
|---|---|---|---|
| OSM 校园路网数据不完整 | 中 | 高 | 手动补录关键道路，或使用自定义路网；前端高德底图可部分弥补展示层缺失 |
| DEM 精度不足以做校园尺度坡度分析 | 中 | 中 | V1 先忽略坡度，用道路属性替代 |
| LLM 空间约束提取准确率不达标 | 中 | 高 | 优化 Prompt，增加 few-shot 示例，限制约束维度 |
| API 调用延迟导致用户体验差 | 低 | 低 | 使用轻量模型（如 gpt-4o-mini），前端加 loading 动画 |
| 个人开发时间不足 | 中 | 高 | 严格限定 V1 范围，优先核心链路 |
| 地名模糊导致坐标解析失败 | 中 | 中 | 硬编码 POI 名称映射表作为 fallback |
| Render 免费部署休眠 | 高 | 低 | 首次访问需冷启动（~30 秒），可接受 |
