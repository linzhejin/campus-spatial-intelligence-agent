# 课程空间数据融合与验收

## 融合原则

- 保留 **OSM 路网 + 高德在线服务** 的混合架构。OSM 是开放底稿；课程数据在可唯一对应的道路上补充静态属性，并以步行专用平行边加入校方几何；原 OSM 边保留其原几何和出行权限。高德仅在线提供底图、POI/路线参照，不将商业 API 返回数据并入可再发布的路网。
- 课程数据来自本机课程目录 `C:\Users\HUAWEI\Desktop\homework\空间分析练习\2026空间分析\RoadNet`，包含 `whu_road.shp`、`whu_spot.shp` 及其 sidecar。道路和地点原始 CRS 为 EPSG:4547。源文件不复制进应用仓库。
- 坐标仅按数据流转需要转换：道路线存 WGS-84；前端高德底图与正式 POI 坐标用 GCJ-02。课程地点从 WGS-84 转 GCJ-02 一次。坐标转换不等于现场核实，也不能补出缺失的路。
- `data/whu_road_network_osm_base.graphml` 是可重复构建的只读 OSM 输入，`data/whu_road_network.graphml` 是应用实际读取的融合运行图；重建永远从前者开始，避免重复叠加课程数据。
- 课程道路线的 Z 值全为 0，不是实测高程；本轮不生成坡度、海拔或风景评分。原有路线属性只在来源、对应关系和空间几何检查通过后保留；数据未知就保持未知。
- 课程数据没有提供明确再发布许可，发布包记录 `not_established`。OSM 衍生内容仍按 ODbL 管理；地图商路线折线不落入正式主库。

## 当前已入库内容

正式 POI 数量为 440，没有重复 ID。`data/pois.json` 中 5 个已有地点由课程点位校正坐标，并增加课程来源与坐标历史：遥感学院对应 `poi_247`、校门牌坊对应 `poi_140`、校史馆对应 `poi_034`、行政楼对应 `poi_035`、万林博物馆对应 `poi_004`。遥感学院新增常用别名“遥感学院”“信息学部遥感学院”；校门点增加“武汉大学校门牌坊”等别名。它们的课程来源状态是 `source_only`，不能称作现场核实。

道路源有 647 条。源匹配器分类为 197 条匹配、440 条歧义、10 条新候选；这是匹配阶段分类，不等于最终入库数量。按用户确认校方静态道路几何可信、但现时通行属性未知的规则，发布校验中：

- 88 条唯一匹配课程道路生成了 322 条有向的步行专用几何副本；原 OSM 有向边及其模式权限保持不变。每条副本都记录 OSM 与课程来源。
- 159 条唯一匹配课程道路应用了静态属性，其中 71 条只应用属性、保留 OSM 几何；一共影响 710 条有向边。静态冲突不会按输入先后任意覆盖。
- 197 条匹配道路全部应用了安全通过的几何或静态属性；其中 88 条加入步行专用几何副本、159 条应用静态属性（两类有重叠）。其余 485 条校方几何作为独立步行专用边加入，不删除 OSM 原边。所有校方几何都从骑行和驾车图排除。
- 647 条源道路中，644 条在正式步行图中可追溯；第 393、394 行是用户指定保留的自强大道拓扑练习断点，第 265 行是源数据标注的施工边。这三条仍完整显示在校方参考图层，但不作为新增步行边。
- 属性覆盖数不代表实地通行核实。课程没有坡度数据，新增内容不调整最短路权重或通行权限。

## 自强大道拓扑例外

用户确认珞珈广场旁课程道路第 393、394 行的断开是课程拓扑练习的一部分，不能当作封路。实测课程折线端点间距约 140.29 米；两端分别吸附到原 OSM 节点，距离约 4.05 米和 2.30 米。原 OSM 步行路网与融合发布图都保留约 161.51 米的步行连通路线。

此决定写在 `data/course_topology_exceptions.json`，证据状态为用户提供、尚非现场核实。构建时会拦截步行封禁、失去原步行连通、端点无法安全吸附或将断开的课程线误激活为孤立新连接器。它不会生成跨越约 140 米缺口的直线，也不会把自强大道标为关闭。

## 构建、审计与剩余事项

本机重新构建命令：

```powershell
python scripts/network/build_course_data_release.py `
```

### 玉兰2门与信息—文理连接路

前一版把“课程点位层没有玉兰2门门点”错误地写成了“课程数据不含连接道路”。两者需要分开：`whu_spot` 没有名为玉兰2门的点；`whu_road` 有该区域的校方路段。高德 `place/text` 对“玉兰2门”“玉兰二门”均未返回独立 POI，但用户提供的高德底图截图有此地图标注，因此 API 未命中不能解释为门不存在。

正式库现以 `poi_449` 收录“玉兰2门”，别名包含“玉兰二门”和“武汉大学玉兰2门”。位置绑定到 OSM `node/1204194363`（`barrier=gate`、`foot=yes`）；节点坐标由 WGS-84 转 GCJ-02。高德截图估点与该节点相距约 14.4 米，估点不确定度约 25 米。门名与存在由用户确认；具体坐标仍标为 `source_only`，不能称作现场测量或精确门牌核实。

连接路由的漏项在拓扑而非道路几何：课程道路第 210、270 行组成的新步行路段已进入图，但共享路口 `13732671009` 与校门 OSM 节点相距 4.937 米。旧融合流程只把整组新道路的外端接到 OSM，没有检查内部路口附近的校门节点，所以“路段在图中”不代表“从校门可以走上该路”。`data/course_junction_overrides.json` 现在记录这个精确连接：两个方向均可步行，最大容许缝隙 5.5 米，目标节点必须是有步行许可的 OSM gate。OSM 建筑轮廓快照检查了 750 个建筑面，连接线没有相交，最近建筑约 5.048 米。当前发布图验证了从该门到课程连接道路两个外部锚点的步行连通。

“澄波门”已在正式库中，记录为 `poi_419`，来源是 OSM `node/1197839325`，状态仍为 `source_only`；其 OSM 步行标签为 `foot=permit`，通行范围仍受门禁规则约束。

“卓尔体育馆”已存在于正式库，记录为 `poi_418`，不是课程点位新增项。当前图上从 POI 中心到最近路网节点约 57.6 米；线上比较时，高德入口与 POI 中心相距约 97.9 米，但路线实际从同一个高德入口起步。入口在线解析可改善落点，离线 POI 中心仍需现场或校方核实，不能把其中任一坐标直接宣称为实测入口。

## 几何与路线复核快照（2026-09-28）

- 切分道路时曾把 WGS-84 节点误当成 EPSG:4547 米制点逆变换，导致 4 条边被拉到赤道附近、最长边达到约 6,842 公里。现已修正为直接把 WGS-84 节点投影到米制坐标；融合图为 4,579 个节点、12,570 条有向边，最长单边约 905.48 米，发布构建会拒绝校界外几何和超过 10 公里的单边。
- `data/edge_attribute_master.json` 已重建到当前图：12,570 条边各有一条唯一绑定；新加的 2 条校门连接边也有独立记录，图版本指纹匹配。课程替换几何对应的旧 DEM/坡度记录已清空，保持未知；不再把旧形状的坡度值继承到新线位。
- `scripts/fetch/osm_building_footprints.py` 从 OSM API 0.6 获取校界范围内建筑轮廓，生成 750 个有效校内建筑面。它们只用于路线相交预警，不表示建筑内部通行；审计输出注明 ODbL 和来源指纹，不进入应用路网或商业地图数据包。
- 六组高德步行对照均已从相同导航入口计算，自有路线统一使用最短距离权重 `1/0/0`；接口 6/6 返回。仍有 4 组几何或距离差异超过门槛，另有 7 条去重后的路线边与开放建筑轮廓相交，包含已标注的 `corridor/bridge` 连廊候选和一条普通步行道路候选。它们是待核查线索，不能据此自动封路或判定高德为真值。
- 正式验收仍未通过：298 个 OSM 地点候选待逐项纳入/排除；440 个 POI 没有现场或校方核实；9 个 POI 到最近图节点超过 50 米；9,510 条旧坡度/风景记录带占位说明；6 组路线没有现场通行证据。课程数据再发布许可也未建立，因此当前结果不能标成已现场验证或直接作为公开部署数据。

以上快照由自动结构、拓扑、几何和 API 对照生成，不替代实地通行核验。重新获取建筑轮廓：

```powershell

```
