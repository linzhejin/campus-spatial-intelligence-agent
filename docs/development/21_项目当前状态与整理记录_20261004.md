## 一页结论

项目已具备可运行的校园时空智能体产品：自然语言路线任务、结构化多轮路线状态、校园路网与地点查询、路线偏好、用户端网页/Android 壳应用，以及独立的道路管理和机载影像人工复核流程。核心研究方向可进入对照实验，不必等全校每条道路都完成现场测量。

当前主要限制是证据成熟度，而不是功能空白：C1 结果来自重复使用的开发集；全库数据发布审计仍未通过；没有武大现场影像真值，也没有事故识别；并发任务、真实用户体验和关键路线几何仍需独立评估。因此，项目适合边补关键能力边推进论文实验，但目前证据还不能支撑“全校道路均可靠”或“机载事故/拥堵已达到现场精度”等结论。

## 数据和研究证据的日期边界

2026-10-01 的历史快照记录 440 个正式 POI、17 个校门、5,087 个路网节点和 14,622 条有向边。严格发布检查当时有 11 类待处理/待核查项，包括 298 个候选未裁决、9,510 条道路属性带占位说明、1,202 条风险边以及代表路线缺现场证据；六组路网与地图商路线对照中有三组差异需解释，另有九条边与建筑轮廓相交待核查。它们分别表示审计待办和几何疑点，不能直接解释成实际道路错误或穿楼。

研究侧已有 C1 多轮状态保持的工程对照；研究矩阵仍是方案草案。下一步应冻结独立任务集和判分，再补少量关键路线/空间工具核查及真实用户评价。公开机载图像实验须报告其公开数据边界，不外推为武汉大学现场精度。来源详见[数据基础评测](18_项目进度与基础评测_20261001.md)、[研究矩阵](../research/01_研究问题与实验验收矩阵.md)、[C1 预实验](../research/03_C1多轮智能体对照预实验结果_20261003.md)、[视觉验收](19_视觉图像识别功能实施与验收_20261003.md)和[管理端验收](20_管理端双流程实施与验收_20261003.md)。

## 后续目录整理方案

这次只做低风险归档和文档入口统一；不整体重排代码包或 `data/`。推荐后续按以下顺序做，每步先盘点引用再改路径：

1. **维持源码包边界。** Agent、API、空间逻辑、存储/任务、视觉、静态前端和 Android 各留在现有职责目录；先补齐根 README 与架构图，避免为“看起来整齐”改导入路径。
2. **先给 `data/` 建来源清单。** 按主数据、候选、审查决策、派生/缓存、运行数据登记文件、来源、授权、生成脚本和代码引用；先完善清单，不移动文件。
3. **隔离运行期文件。** 若今后调整，先在兼容读取层支持旧/新路径，迁移后比对行数、关键 ID、哈希和服务读写，再移除旧路径；运行事件和用户数据必须备份。
4. **统一实验产物。** 每次实验将冻结任务集、配置、版本号、原始结果和汇总指标绑定；只有可复现且适合公开的证据入库，本机大文件继续留在 ignored 输出目录。
5. **再处理 `legacy/` 与根目录。** 只有确认无导入、构建和部署引用后才归档；不删除来源不明或权限受限内容。
