# Agent 平台收敛实施记录

更新日期：2026-09-30

## 实施目标

在保留现有 Flask、LangGraph、校园自有/OSM 路网和高德地图混合架构的前提下，修复对话上下文串扰、并发任务互相阻塞和进度不可追踪的问题；提供独立的管理者路况界面；搭好机载影像审核流程，避免未核实的模型输出直接影响导航。

## 已落地

### 会话与任务状态

- PostgreSQL 保存会话、任务快照、消息、修订历史、任务运行和事件；迁移位于 `storage/migrations/`，由 `storage/database.py` 按版本应用。
- Pydantic 合同限制坐标系、权重和路线字段；任务修改带 `base_revision` 做 compare-and-swap。过期澄清会返回 `task_revision_conflict`，重复/篡改请求编号返回 `idempotency_conflict`。
- 路线状态只会在同一澄清任务或用户明确指向上一条路线时进入上下文；独立天气/闲聊不继承旧路线槽位。前端不同请求拥有独立气泡和完成状态，切换出行方式不清空或交换起终点。
- 路线与天气的明确组合并行处理，可部分成功并说明失败项；仅天气任务走确定性天气工具。天气与 POI/路况混合问题交由完整工具 Agent，避免被天气快捷处理吞掉。
- 后台 worker 使用 Postgres 租约、心跳、取消与过期结果保护；支持多 worker 并发，不让长时间模型调用占住 Web 请求。
- 页面恢复带会话代次和用户轮次校验；恢复请求期间若用户重置或发起新任务，迟到的历史响应不会覆盖当前上下文。
- 每个已完成任务的回复记录其对应用户消息序号。新旧路线比较以用户请求顺序为准，因此较早请求即使较晚完成，也不会覆盖新路线或在刷新后被误恢复为最新路线。
- worker 身份放在 LangGraph 本次调用的运行时上下文中，不再依赖 checkpoint 里的旧 worker 身份；租约被另一 worker 接管后，恢复节点仍以新租约身份记录事件。
- 澄清续答优先识别明确路线槽位；裸地点名只有在待回答问题确实询问地点且 POI 名称/别名精确匹配时才续接。地点检索失败时按独立请求处理，避免误改旧任务。

### 管理者入口

- `/manager` 为独立管理台，管理员登录后可查看/新增/结束/删除绑定到实际路段的路况事件。
- session 写操作要求 CSRF 令牌；系统间 Token 继续使用常量时间比较。管理台仍依赖现有共享口令或 Token，当前没有组织账号、角色或细粒度 RBAC。

### 机载影像审核管线

- 私有上传目录、任务数据库队列、独立视觉 worker、状态轮询、原始媒体授权读取和单次审核决定已经接通。
- 分析边界是保守的：单帧只能形成车辆聚集候选；视频拥堵候选要求机位固定或已稳像，并有连续车辆跟踪和低位移证据。事故候选需要检测模型明确提供事故类标签。
- 所有输出带 `review_required=true`、`auto_publish=false`；管理员确认影像候选后，仍需在管理台选具体道路并手动发布事件。标注点只是粗略观察区域，不是无人机影像检测框的地面坐标。
- 视觉依赖不加入 Web API 基础依赖；模型只能从 `VISION_MODEL_PATH` 读取本机文件，不会因用户上传触发下载。视频默认使用 BoT-SORT，但这不等于相机运动已被补偿。
- 上传文件与解码帧都有限额；图片先检查头部尺寸，视频先检查容器标注分辨率并逐帧复核，避免超大画面拖垮独立 worker。
- 模型/依赖未就绪时，管理台禁用提交，服务端也拒绝直接上传入队，避免留下必然失败的影像任务。
- 管理台就绪判断还要求数据库中存在 30 秒内的视觉 worker 心跳；worker 只有实际加载本地模型后才报告就绪，优雅停止时立即撤销就绪。部署脚本仅在本地权重和视觉依赖齐备时安装并启用独立视觉 systemd 服务。
- Agent worker 由常驻监督器维护固定并发槽；单槽初始化失败后指数退避补位，避免服务显示 active 但实际并发数永久下降。
- 管理台每 5 秒同步视觉就绪状态；上传中保持按钮锁定，网络查询异常时关闭提交，防止重复入队或给出过时的可用状态。视觉 systemd 停止宽限期 300 秒，覆盖单任务 240 秒的处理时限。

## 启用条件与当前限制

1. **持久 Agent 上线需要 PostgreSQL。** 生产 Web 和 `python -m jobs.worker` 必须使用同一个 `DATABASE_URL` 与兼容代码版本；仅更新 Web 代码而不启动 worker 时，任务会保持排队。
2. **当前开发机没有已验证的视觉模型推理环境。** `ultralytics` / OpenCV 属于可选依赖，必须单独安装；还需提供本地权重后管理端才允许提交影像分析。此提交实现了功能管线和安全审核，不宣称检测模型已经校准或可用于真实航管。
3. **事故识别仍需事故标注数据和专用模型。** 通用 COCO 车辆类别不能证明发生事故。移动无人机拥堵识别还需相机运动补偿、视频时间戳/尺度校准和影像到道路的配准。视觉推理在独立进程运行；可选依赖和模型文件路径需对 Web 与 worker 共享，避免管理台错误显示就绪状态。
4. **公开数据使用仍需逐数据集核验授权。** 已研究的 VisDrone 官方仓库可用于发现数据内容与下载入口，但未找到足以确认再分发/模型权重发布权的清晰许可，因此没有自动下载或把该数据集/权重打包进仓库。任何训练成果先核验许可证、数据说明及图片再发布限制。
5. 上传文件目前没有自动保留期；上线前应依据管理员审核和校方数据政策设置保留、导出与删除流程。管理员身份仍是共享口令/Token。

## 运行方式

```powershell
# Web API
python app.py

# 持久 Agent 任务消费者（同一数据库配置）
python -m jobs.worker

# 可选：在 Web 共用虚拟环境安装 requirements-vision.txt，并设置双方可读的本地模型路径后
python -m vision.worker
```

配置项示例见仓库根目录 `.env.example`；部署说明见 `docs/03_部署指南.md`。不要把 `.env`、API key、私有影像或模型权重提交到 Git。

## 验收证据

- Python 全库回归：执行 `python -m pytest -q`，检查报告记录通过、跳过、预期失败及所有失败的具体数目。
- 前端会话与路线状态回归：执行 `node --check static/js/app.js`、`node --check static/js/manager.js` 和 `node --test tests/js/*.test.js`。
- 专项覆盖：多轮上下文隔离、重复/过期提交、跨会话访问、并行 run、取消与过期租约、CSRF、媒体签名/范围校验、机位稳定条件、审核一次性和道路事件绑定。
- 这些软件用例不替代校园现场通行核查，也不证明影像模型在真实校园航拍上的准确率；后续论文评测需另外构造带真值的校园样本与对照实验。
