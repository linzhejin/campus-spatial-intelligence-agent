# 观察区域大图切片推理修复（2026-10-10）

## 问题与改动

原来的观察区域推理把整个多边形外接矩形一次缩放到 960×960。对 1080p 或更大的圈选区域，这会明显压小画面中的行人和车辆。现在改为：

- 观察区域不超过模型输入尺度时仍一次推理。
- 大区域切成最多约 1.25 倍模型输入边长的重叠窗口；当前模型输入为 960，因此源画面窗口最大为 1200×1200，推理时缩小约 20%。窗口按完整覆盖范围均匀分布，重叠约 20%，并恢复到原始帧坐标。
- 只合并同类别且高度重叠的跨窗检测框；若较高置信度的框被窗口边界截断，会用相邻窗口的重复框补齐外沿。
- 全帧未圈选观察区域时仍沿用原有单次整帧推理。视频跟踪与候选分析继续使用恢复后的原始帧坐标。

此实现改善大观察区域的小目标输入尺度，但不是正射校正、道路坐标定位或校园识别精度验证。管理员仍须圈选实际观察区域并复核事件与路段。

## 验收证据

- 回归测试先在旧实现上失败（大观察区域只调用一次推理），实现后通过；覆盖 2400×1200 区域切片、重叠目标去重、边界框坐标恢复，以及普通小区域保持原流程。
- 使用本机 `visdrone-rtdetrv4-s.onnx` 对合成黑色 1920×1080 画面重复推理：整帧推理中位数 **0.901 秒**，全帧 ROI 两块切片中位数 **3.662 秒**。这只衡量本机 CPU 流程开销，黑色画面不用于模型准确率判断；大 ROI 会更慢，实际航拍建议只圈选道路、人行区域，后续再按实测决定是否迁移 GPU。
- 本机全库 Python：**1035 passed、48 skipped、1 xfailed**；跳过项依赖独立 PostgreSQL 集成环境。JavaScript：**113 passed**。`python -m compileall -q api storage vision tests/test_vision_onnx_detector.py`、`python scripts/docs/gen_facts.py --check` 和 `git diff --check` 均通过。
- 提交 **`0952596`** 已推送至 GitHub、Gitee 的 `main`，并快进部署到腾讯云项目目录。部署前视觉任务队列无 queued/running 任务；没有数据库迁移或模型权重变化。
- 部署后 `whu-walker`、`whu-agent-worker`、`whu-vision-worker` 均为 active；视觉 worker 数据库心跳为 ready，最近心跳约 5 秒；公网 `/health` 返回 HTTP 200、`status=ok`。服务器原有未跟踪文件 `cloudflared`、`scripts/_probe_shortest.py`、`wget-log` 保持原样。
- 发布只证明切片代码和服务已更新，不代表武大航拍识别效果。无现场样本、事故与积水模型仍关闭。
