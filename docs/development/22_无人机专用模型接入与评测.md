# 无人机事故与积水模型接入及评测

## 可加载模型约定

视觉 worker 只从本机路径加载 ONNX；上传影像不会触发联网下载。事故模型与积水模型各自加载、各自报错。任一可选模型权重缺失、格式不符或推理失败时，基础人车检测仍可继续。

| 能力 | 输入和输出约定 | 结果边界 |
|---|---|---|
| 事故场景分类 | 单输入 `[N,3,H,W]`、固定 RGB 224×224、ImageNet 均值/标准差归一化；输出五类分数，顺序为 `collapsed_building, fire, flooded_areas, normal, traffic_incident` | 输出画面级线索。连续画面达到阈值才生成待审核候选，不表示事故车辆坐标或现场道路已定位 |
| 道路积水分割 | 单输入 `[N,3,H,W]`、固定 RGB 尺寸；输出 `[N,10,H,W]`，FloodNet 第 3 类（从 0 开始）为 `flooded_road` | 只处理管理员圈定的“路面”区域；输出画面像素占比和轮廓，不推测真实面积或水深 |

每一模型的 ONNX 输入尺寸、输出维度和类别数在加载时检查。管理台显示实际视觉 worker 能力，不根据配置文件里写了路径就误报“已启用”。

## 测试集清单

评测工具不自行随机拆分帧。清单必须登记按航次、独立场景或事故事件分组的训练、验证和测试组；三组不能重叠，样本必须属于测试组。清单中填写相对于 `--dataset-root` 的文件路径。

事故分类清单示例：

```json
{
  "schema_version": 1,
  "task": "accident_classification",
  "dataset": "AIDER local held-out test",
  "split_unit": "incident_scene",
  "split_groups": {
    "train": ["scene-001", "scene-002"],
    "validation": ["scene-003"],
    "test": ["scene-004", "scene-005"]
  },
  "class_order": [
    "collapsed_building", "fire", "flooded_areas", "normal", "traffic_incident"
  ],
  "samples": [
    {"image": "test/scene-004/frame-001.jpg", "group_id": "scene-004", "label": "traffic_incident"},
    {"image": "test/scene-005/frame-010.jpg", "group_id": "scene-005", "label": "normal"}
  ]
}
```

积水清单中每张测试影像对应一张同尺寸、灰度类别索引掩膜；掩膜像素值 3 表示 `flooded_road`。还需要给出归一化到 0–1 的道路多边形：

```json
{
  "schema_version": 1,
  "task": "flooded_road_segmentation",
  "dataset": "FloodNet local held-out test",
  "split_unit": "flight_or_scene",
  "split_groups": {
    "train": ["flight-a", "flight-b"],
    "validation": ["flight-c"],
    "test": ["flight-d"]
  },
  "samples": [
    {
      "image": "test/flight-d/image-001.jpg",
      "mask": "test/flight-d/mask-001.png",
      "group_id": "flight-d",
      "flooded_road_class_id": 3,
      "road_surface_polygon": [[0.12, 0.38], [0.88, 0.35], [0.91, 0.72], [0.10, 0.76]]
    }
  ]
}
```

执行示例：

```powershell
python scripts/vision/evaluate_specialized.py `
  --task accident_classification `
  --manifest D:\LuoJiaExperimentData\AIDER\held-out.json `
  --dataset-root D:\LuoJiaExperimentData\AIDER `
  --model D:\LuoJiaModels\aider-five-class.onnx `
  --threshold 0.85 `
  --output data\vision\reports\aider-held-out.json

python scripts/vision/evaluate_specialized.py `
  --task flooded_road_segmentation `
  --manifest D:\LuoJiaExperimentData\FloodNet\held-out.json `
  --dataset-root D:\LuoJiaExperimentData\FloodNet `
  --model D:\LuoJiaModels\floodnet-mobilenetv3-unet.onnx `
  --output data\vision\reports\floodnet-held-out.json
```

报告包含模型和清单 SHA256、逐类分类结果或路面 ROI 像素 IoU、推理时间及按独立组重采样得到的 95% 区间。测试组少于两个时，置信区间标为空，不能用帧数伪装成独立样本数。

## 训练与授权边界

- [TakuNet 的 AIDER 数据读取器](https://raw.githubusercontent.com/DanielRossi1/TakuNet/main/src/datasets/aider.py)按类别目录排序读取五类；其仓库配置不能代替本项目的航次/场景级留出验证。本项目没有复制其代码或权重。
- [FloodNet 官方仓库](https://github.com/BinaLab/FloodNet-Supervised_v1.0)提供灾后无人机影像和语义分割标注，可用于公开集基线；自然灾后影像与校园浅积水差异很大，公开指标不能直接作为武大效果。
- 本仓库目前**提供模型加载、评测入口和分组清单约束，不包含事故/积水训练器，也没有生成可用权重**。当前本地没有 AIDER/FloodNet 数据及 PyTorch 训练环境，不能在这里真实训练或报告其精度。待获得数据、权重和可用算力后，训练流程应保存数据/权重许可、训练组、验证组、超参数、最佳检查点哈希，并用上述脚本在独立测试组出报告。
- AIDER/TakuNet 源项目尚需逐项核实再分发许可；在确认前不要把下载的影像、训练权重或第三方实现提交到仓库或部署服务器。
- 当前车辆和行人视频跟踪器实现了高分框优先、低分框延续的两阶段 IoU 关联，代码明确标作 `bytetrack_style_two_stage_iou`。它不是官方 ByteTrack，也没有卡尔曼预测/Hungarian 匹配，不能宣称为原版 ByteTrack 或引用原论文性能；应在获取航拍视频后与官方实现做固定样本对照再决定是否替换。

事故和积水结果默认仅进入管理员逐条复核。管理员确认具体路段、出行方式和有效时间之前，任何识别结果都不会直接改变用户路线。
