# C1 多轮时空任务对照预实验

## 状态与目的

- 使用 `academic-research-suite` 的 `experiment-agent` 执行与验证流程。
- 本轮为开发预实验，任务由项目组编写；失败样本可用于修复，因此本轮结果**不能**作为论文的独立留出集成绩。
- 检验对象是同一线上服务对多轮任务状态的保持与工具执行；不将 OSM、高德或现场路段差异算作智能体提升。

## 冻结设计

- 任务集：`experiments/datasets/c1_live_pilot_v1.json`，30 个预写目标，涵盖路线偏好、出行方式、插入天气/地点问题、途经点、台阶和坡度约束、起终点修正、先澄清后回答，以及独立新任务。任务集在首次完整运行前提交到 Git，记录 SHA256。
- 完整组：在一个会话中依次发送准备消息与目标消息；当服务返回待补充输入时，携带任务 ID 与版本继续。
- 无状态组：在新会话中只发送**完全相同的目标消息**。两组均使用同一线上代码、POI、路网、事件快照和模型配置；轮流先跑哪一组以减小时间顺序影响。此组只能检验会话上下文的增益，不能代表另一套完整智能体架构。
- 判分：只检查每题预写的响应类别、起终点、途经点、出行方式、路线策略、硬约束和复合需求结果；地点正式名与本次 POI 快照中的**唯一别名**视为同一地点，歧义别名不自动等价。未知或缺失字段一律不通过。
- 输出：只留任务字段和耗时，不保存位置轨迹、路线几何、会话 Cookie 或用户身份。记下任务集、程序、服务器代码和空间数据指纹。

## 工程验收与论文边界

预实验工程门槛为：完整组至少 `27/30` 题通过；返回了路线的题目中，已知起终点、途经点和硬约束误置为 `0`；完整组通过率不低于无状态组；所有 30 题有可追溯结果。报告配对成功率差及 bootstrap 95% 区间、关键错误数和目标轮 P50/P95 时延，不把区间跨零或小样本差异写成显著性证明。

若不达门槛，保留本轮失败结果，修复产品后在相同任务集上复跑并明确标注“开发集复跑”。正式论文实验另建独立留出集，冻结代码/数据/任务/判分规则后仅评估一次；预实验高分不等于现场道路可通行或真人体验已验证。

## 运行顺序

1. 核对线上代码与 POI、路网 Git blob 指纹；记录路况事件快照及不可控外部服务状态。
2. 执行 30 题配对预实验，按失败类型定位根因，添加回归测试并修复。
3. 用最终版本重新执行全部任务；复核结果、常规项目测试和线上运行状态，再提交并部署。
4. 将开发集与未来正式留出集严格区分。资料不足的空间通行事实标为未知。
