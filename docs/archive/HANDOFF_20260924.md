## 1. 项目是什么

**珞珈智行（WHU-Walker）**——武汉大学校园空间智能体，线上 https://whuspati.online 。
自然语言 → 全 Agent（Plan-Act-Observe + function calling）→ 三校区多因素路径规划 → Leaflet 地图 / 语音交付。支持步行/骑行/驾车、按住说话语音输入、路口级步行导航、Android APK（v1.4.1, versionCode 6）。

研究主线：**大模型能否把模糊自然语言空间偏好转换为可计算的空间参数（权重/约束）**。日常通勤路线已改为距离主导，不绕路看景。

## 4. 核心请求链路

```
POST /api/chat
 → agents/planner.py  run_agent()：agent_system.txt + 任务卡 + 画像 + 多轮历史
 → agents/tools.py    LLM 只做决策，10 工具：
     resolve_poi / search_poi_candidates
     plan_route / plan_via_route / plan_tour / plan_multimodal_route
     get_weather / list_road_conditions / ask_user / suggest_followup
 → spatial/routing.py 模式过滤 → 硬约束删边 → 路况/天气成本 → 加权 Dijkstra
 → 坐标转 GCJ-02 → 前端 app.js renderRoute / navigation.js
```

路线规划成功后**立即结束 Agent 循环**直接生成自然语言答复，禁止 LLM 再调 suggest_followup（防 DSML 泄漏）。

## 8. 给 Codex 的硬规则（踩过的坑）

- 坐标系：POI / 前端 / 路况点击 = **GCJ-02**；OSM 路网 / DEM / 原生 GPS = **WGS-84**，边界必须转换；前端底图只用高德 GCJ-02 矢量(style=8)/卫星(webst)，禁接 OSM/Esri 瓦片。
- POI 纪律：仅三学部；排除校外地点、教工宿舍/家属区；小商铺用 is_minor 标；别名必须做中文数字归一（七舍=7舍）；学部名/园区名等宽泛词禁止做别名。
- 路况对三种方式统一生效，步行不得豁免；管理端接口双通道鉴权（网页 session + X-Admin-Token），普通用户只见生效中事件。
- 台阶/电梯/扶梯对 bike/drive 一票否决；步行台阶 2.5×；食堂区域 10 条有向边 10× 软惩罚防穿楼。
- 切换出行方式时用上次路线起终点**坐标**直接重算，禁止把"我的位置"当 POI 名查询。
- 前端 requestSeq 防旧响应覆盖新 UI；非路径响应必须清空地图路线与结果区。
- 确定性逻辑放 tools.py / spatial/，LLM 只决策不计算；parser/temperature 保持 0.0。
- 改 prompts/ 模板后必须重启服务（有进程内缓存）。新增工具要同时改 tools.py、agent_system.txt、tests/test_planner.py。
- 改 POI/路网后跑 validate_all_data.py + 对应 pytest；任何改动后全量 pytest 必须保持 381 全过。
- 不要全量重写大文件（app.js 约 3400 行），用最小编辑；不要新建多余文档/脚本，临时脚本命名 `_tmp_*`（已 gitignore）。
