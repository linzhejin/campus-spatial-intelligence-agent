# 10 · 移动端与语音导航

本篇说明 Android 壳应用、语音输入 / 播报与实时导航的端到端实现。代码位置：[android-app/](../android-app/)（仅两个 Java 类 + Manifest，零第三方依赖）、[static/js/voice-input.js](../static/js/voice-input.js)、[static/js/voice-output.js](../static/js/voice-output.js)、[static/js/navigation.js](../static/js/navigation.js)，后端转向指令在 [spatial/routing.py](../spatial/routing.py) 的 `build_turn_by_turn`。

## 1. 架构：WebView 壳 + 同一套 PWA 前端

`MainActivity` 全屏 WebView 直接加载 `https://whuspati.online/`，开启 JS、DOM storage、媒体自动播放（`setMediaPlaybackRequiresUserGesture(false)`，导航语音不需要点击解锁）、禁明文流量（HTTPS only）。浏览器和 App 跑的是**同一套网页代码**，能力差异全部通过 User-Agent 与 JS 桥探测：

- UA 追加 ` WHUWalkerApp/1.4.1`，网页据此抑制安装横幅、改走原生定位 / ASR / TTS。
- 四个 `@JavascriptInterface` 桥（[MainActivity.java](../android-app/src/online/whuspati/app/MainActivity.java)）：

| 桥对象 | 方法 | 用途 |
|---|---|---|
| `WhuWalkerTts` | `speak(text)` / `stop()` / `setMuted(bool)` / `isReady()` | 原生语音播报，speak 返回是否受理 |
| `WhuWalkerVoice` | `press()` / `release()` / `cancel()`（另有兼容旧缓存的 `start/stop`） | 按住说话式语音识别 |
| `WhuWalkerLocation` | `start()` / `stop()` | 原生 GPS/网络定位 + 罗盘融合航向 |
| `WhuWalkerScreen` | `setKeepScreenOn(bool)` | 导航中屏幕常亮 |

原生 → 网页的回调统一经 `webView.evaluateJavascript` 调三个全局函数：`window.__whuWalkerVoiceCallback(json)`（start / level / partial / final / end / error）、`window.__whuWalkerLocationCallback(json)`（fix / error）、`window.__whuWalkerTtsCallback(json)`（unavailable / error / volume0）。

Manifest（[AndroidManifest.xml](../android-app/AndroidManifest.xml)）要点：包名 `online.whuspati.app`，minSdk 26 / targetSdk 34；权限 `INTERNET`、`ACCESS_FINE/COARSE_LOCATION`、`RECORD_AUDIO`、`REQUEST_INSTALL_PACKAGES`；`singleTask` 启动模式；声明 `<queries>` 枚举 `android.speech.RecognitionService`（见下）；自带极简 `ApkFileProvider`（不依赖 androidx），只授权白名单文件名给系统安装器。

## 2. 版本链与应用内更新

当前版本 **versionName 1.4.1 / versionCode 6**（Manifest 与 build.ps1 中各写一份）。更新信息在 [static/app/latest.json](../static/app/latest.json)：`versionCode`、`versionName`、`apkUrl`（固定 https://whuspati.online/app/whu-walker.apk ）、`sha256`、`publishedAt`、`changelog`。

更新流程全部在原生侧完成（不经 Service Worker）：

1. 启动 4 秒后后台线程 GET `latest.json?t=<时间戳>`（no-cache，连接 / 读取各 8s 超时，失败完全无感）；
2. `versionCode` 大于当前、且不在"以后再说"24 小时免打扰窗口内，才回主线程弹窗（一次运行最多弹一次），展示 changelog；
3. 点「立即更新」弹出带进度条的下载对话框，后台线程下载到 `getExternalFilesDir(Downloads)/whu-walker-update.apk`（先写 `.tmp`，连接 15s / 读取 30s 超时，可取消）；
4. 下载完成后三重校验：小于 30KB 判为网关错误页、头两字节必须是 ZIP 魔数 `PK`、清单提供 sha256 时强制逐字节比对，任一不过删除文件并提示；
5. 需要「安装未知应用」授权时跳系统设置，`onResume` 回来自动继续；通过 `ApkFileProvider` 生成 `content://online.whuspati.app.fileprovider/apk/whu-walker-update.apk`（文件名白名单 + 规范路径校验），拉起系统安装器，用户点一次确认即覆盖安装，签名与数据不变。

**为什么 v1.2 用户需要手动重装一次**：v1.2 的更新器把"APK 小于 100KB"硬编码成异常判据，而本应用是零依赖 WebView 壳，真实包体只有约 70KB——v1.2 会把新包误判为"过小"拒绝安装，所以那一代用户无法走应用内更新，必须手动侧载一次新版（新版判据已放宽到 30KB 并增加 PK / SHA-256 校验）。作为双保险，[build.ps1](../android-app/build.ps1) 还会在签名前塞入 64KB 不可压缩随机数据 `assets/pad.dat`（必须随机，zeros 会被 deflate 压没），保证产物 >100KB；该文件运行时从不读取，完整性由 SHA-256 兜住。

## 3. 语音输入（按住说话）

交互时序（网页 pointer 事件 → 桥 → RecognitionService → 回调）：

- 按住麦克风：`press()`，无麦克风权限时先申请，授权回来自动开始；上滑（网页侧 70px 阈值）立即 `cancel()` 丢弃结果；松手 `release()` 结束录音等 final；按住上限 **30 秒**（`MAX_HOLD_MS`）自动松手，松手后 **2.5 秒**没有任何结果则静默收尾（`FINISH_GUARD_MS`），`startListening` 后 2.5s 连 `onReadyForSpeech` 都没有就换下一个识别服务（`START_TIMEOUT_MS`）。
- 不用 `ACTION_RECOGNIZE_SPEECH` 全屏听写面板（国产 ROM 样式不可控、华为上报"似乎出错了呢(2)"），而是用 `SpeechRecognizer.createSpeechRecognizer(context, ComponentName)` **显式绑定厂商 RecognitionService**（华为小艺 / 讯飞 / 小米等），服务依次尝试、全挂才报错。
- **包可见性**：Android 11+ 默认查不到其他应用的服务，Manifest 必须声明 `<queries><intent><action android:name="android.speech.RecognitionService"/></intent></queries>`，`queryIntentServices` 才能枚举出引擎；排序上厂商服务优先、Google 服务置后（国产机 Google 常连不上）。枚举为空（被 ROM 过滤）时，用无参 `createSpeechRecognizer(this)` 绑定**系统默认识别器兜底**；默认也失败才提示"请直接打字 / 系统设置启用语音引擎"。
- 识别参数：zh-CN、free-form、partial results、max results 1。流式 partial 与音量（`onRmsChanged` 的 dB 值映射成 0~1）实时回传，驱动网页聆听胶囊里的转写文字与图标缩放动效。
- 网页侧（voice-input.js）在浏览器 / PWA 内降级 `webkitSpeechRecognition`（zh-CN、interimResults），处理了"onstart 回来前手指已松开"的竞态；微信环境无 SpeechRecognition，给"在浏览器打开"横幅。任何异常只走回调不抛错。

## 4. 语音播报（TTS）

- 原生 `TextToSpeech` 在 onCreate 异步 init，语言依次尝试简体中文 → `Locale.CHINA` → 系统默认；缺中文语音数据时经回调通知网页，网页提示去"设置 → 语言和输入法 → 文字转语音"启用并自动改用浏览器 synth。
- **初始化时序**：init 完成前的 `speak` 不会直接丢掉，最新一条进入 `pendingSpeak`，ready 后补播。
- 播报走 `QUEUE_FLUSH`（新转向指令打断旧播报，导航场景必须及时）；连续 3 次 utterance 失败判引擎故障并通知网页降级；TTS 走 STREAM_MUSIC 媒体音量（与铃声独立），检测到媒体音量为 0 每次运行提示一次。
- 静音状态双向同步：网页静音写 localStorage 并调 `setMuted`；页面隐藏 / 关闭时 `stop()`，避免后台念念有词。

## 5. 实时导航

### 5.1 转向指令在后端生成

`build_turn_by_turn(G, route_nodes, mode, end_name)`（spatial/routing.py）在 WGS-84 路网上先把连续同名道路的边合并成"路段"，再在每个路段边界生成指令：`type` 为 depart / turn / via / arrive，`action` 含直行、稍左 / 左 / 急左（及右）、掉头等，附 `distance_m`、`cumulative_m`、`road_name`、`next_road_name`、中文文案 `text` 与动作点坐标。API 出参时指令点与路线一起转成 GCJ-02，前端不再做坐标计算之外的地理推断。

### 5.2 投影、吸附与偏航（navigation.js）

前端把每个 GPS 定位投影到路线折线的局部米制展开（`buildGeometry` / `projectOn`），拿到沿线里程 progress 与贴线垂直距离 cross，驱动指令状态机与剩余里程：

- 远距预报距离：拐点步行 25m / 骑行 50m / 驾车 100m，终点预报 40/60/80m；≤7m 播临近动作令，剩余 ≤12m 判到达；相邻 <15m 的连续拐点自动合并，depart 与首拐点同点时做让位处理。
- **路段方位角吸附纠偏**：为什么不信罗盘——手机磁罗盘受室内钢结构、姿态和磁偏角影响会持续偏几度到几十度，步行慢速时 GPS bearing 又频繁归零。而人在已知折线上、贴线 ≤30m 且速度 ≥0.5m/s 时，所在路段的方向是确定的：此时箭头直接取路段方位角（与设备航向夹角 >100° 的逆行 / 掉头场景除外，仍显示真实朝向），再做最短角路径低通平滑。
- **跨正北角度展平**：内部航向归一化在 0~360，但显示角不归一——每次只累加最短角差（如 359°→1° 记为 +2°），避免 CSS transition 从 359 逆时针绕一整圈到 1。
- **偏离静默重算**：cross 超阈值（步行 20m / 骑行 30m / 驾车 35m）且不在起终点 30m 内、定位精度 ≤100m，连续 2 点确认即静默 POST `/api/route`（带当前坐标、原终点、原约束权重和当前 mode），冷却 30s；成功后用新路线重建几何与指令，地图交给 app.js 重绘（导航态不 fitBounds），只 toast + 一句"已为您重新规划路线"，不弹任何打断式对话框。
- 10s 无 fix 上抛 GPS 弱网黄条；拖拽地图退出北朝上跟随并显示重居中按钮；Wake Lock（浏览器 Screen Wake Lock + App 内 `WhuWalkerScreen`）保持常亮；速度用 progress 增量做 EMA 估算剩余用时。

### 5.3 GPS 与网络定位分储 + 6 秒优先窗口（原生侧）

`LocationManager` 同时注册 GPS_PROVIDER（1s 间隔）与 NETWORK_PROVIDER（2s 间隔），但两路结果**分开存** `lastGpsFix` / `lastNetFix`，互不顶掉——WiFi 点没有速度，若顶掉 GPS 点会让行走中的航向周期性回落罗盘分支，把罗盘偏差带回箭头。每 500ms 发射一次定位：**GPS fix 在 6 秒内（`now - time ≤ 6000ms`）无条件优先**，GPS 失效（室内 / 天桥下）才退回网络定位。

航向融合：速度 ≥0.6m/s 且 GPS bearing 是 3 秒内的新鲜值时用 GPS bearing（转向响应快、静止漂归零被速度门控挡住）；否则用 ROTATION_VECTOR 传感器（无此传感器的设备退化为加速度计 + 磁力计组合）算出的磁罗盘航向，做屏幕旋转补偿、用 `GeomagneticField` 按当前位置修正磁偏角（武汉约 -3.7°），再经重低通与 0.4 系数融合。坐标以 WGS-84 回传（`{lat,lng,heading,accuracy,speed,src,ts}`），网页渲染前自行转 GCJ-02，重算时直接拿 WGS-84 发给后端。

## 6. 构建工具链

无 Gradle、无第三方库，PowerShell 手工流水线（[build.ps1](../android-app/build.ps1)，工具在仓库同级 `tools/`：build-tools 34（`android-14` 目录）、platform 35 的 android.jar、JDK 17）：

1. `aapt2 compile --dir res` 编译资源；
2. `aapt2 link` 链接（带 manifest、min/target-sdk、versionCode/Name）；
3. `javac --release 8` 编译两个 Java 类；
4. `d8 --min-api 26` 生成 dex；
5. `aapt add classes.dex` 并入 APK（构建前先写入 64KB 随机 pad.dat）；
6. `zipalign -f 4` 四字节对齐；
7. 首次构建用 keytool 生成 `whu-walker.keystore`（alias `whuwalker`，RSA 2048，有效期 10950 天，密码存 `keystore-password.txt`，两者均不提交）；
8. `apksigner sign` 签名；
9. `apksigner verify --print-certs` 验证。

产物是 `android-app/build/whu-walker.apk`（当前发布物约 133KB），需手动拷贝覆盖 [static/app/whu-walker.apk](../static/app/whu-walker.apk) 随站分发（`.gitignore` 用 `!static/app/whu-walker.apk` 例外放行）。

## 7. 发布检查清单

1. 升 `AndroidManifest.xml` 的 `android:versionCode`（必须 +1，安装覆盖以此判断）与 `android:versionName`；
2. 同步改 `build.ps1` 顶部 `$verCode` / `$verName`（两处不互相读取）；
3. 同步改 MainActivity 里硬编码的 UA 后缀 `WHUWalkerApp/1.4.1`（网页按 UA 识别 App 与版本行为，漏改会导致版本误判）；
4. 跑 `build.ps1`，确认 9 步全部通过、apksigner verify 成功；
5. 把 `build/whu-walker.apk` 拷贝覆盖 `static/app/whu-walker.apk`；
6. 计算新包 SHA-256，更新 [static/app/latest.json](../static/app/latest.json) 的 `versionCode` / `versionName` / `sha256` / `publishedAt` / `changelog`（apkUrl 保持同名常量；sha256 填 `pending` 开头会被客户端当作不校验，正式发布必须填真实值）；
7. 确认 [static/sw.js](../static/sw.js) 对 `/app/` 保持 network-only（APK 同名覆盖发版，绝不可进缓存）；
8. 部署后真机验证：启动 4s 后弹更新窗 → 下载进度 → SHA-256 通过 → 跳系统安装器 → 覆盖安装后 versionName 正确、网页缓存与 localStorage 不丢。
