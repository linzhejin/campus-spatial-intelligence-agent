# 坡度与景观路段属性主库设计

**日期：** 2026-09-27

**适用项目：** 珞珈智行（WHU-Walker）

**目标：** 将现有坡度与景观占位字段重建为可追溯、可分级验证、可随路网迁移的路段属性主库，为平坦优先、风景优先、无障碍约束和论文实验提供可信数据基础。

## 1. 当前事实

当前 `data/road_annotations.json` 覆盖 12,550 条路网边，但字段覆盖率不能代表质量：

- 9,510 条记录仍带“占位”说明；
- 约 3,030 条较长路段使用现有 DEM 流程计算坡度；
- 坡度等级分布为：1 级 1,956 条、2 级 498 条、3 级 9,566 条、4 级 338 条、5 级 192 条；
- 景观等级分布为：3 级 11,674 条、4 级 598 条、5 级 278 条，没有 1、2 级；
- 景观等级主要来自附近 POI、道路名称和少量固定道路名单，属于候选启发式；
- 坡度使用路段两端绝对高差，不能区分上坡和下坡；
- 30 米级 DEM 无法可靠解析大量短边、台阶和建筑附近连接；
- 部分 `scripts/network/` 脚本移动目录后仍按旧层级计算项目根目录，存在读写 `scripts/data` 而不是仓库 `data` 的风险；
- 来源与置信度主要写在自由文本 `note` 中，不能稳定审计、统计或迁移。

因此，现有字段只能继续作为候选输入，不能直接作为高权重路线优化的可靠依据。

## 2. 设计选择

采用“多源候选层 → 属性主库 → 审核层 → 发布快照”的数据架构。

被否决的方案：

1. **继续补齐 1–5 等级。** 它会把缺测值包装成完整数据，无法说明来源、误差和置信度。
2. **完全依赖 30 米 DEM 与道路名称。** 前者不能解析短路段，后者不能度量真实景观体验。
3. **直接开展全量现场或无人机测绘。** 成本高，影像表面模型还会混入树冠和建筑；本阶段应先建立可吸收现场证据的主库，再核实高风险路段。

## 3. 数据原则

1. **未知就是未知。** 缺少可靠证据时保存 `null/unknown`，不得用 3 级冒充已知中等值。
2. **连续指标先于等级。** 保存高程、坡度百分比、植被、水体等原始或连续特征，1–5 等级只作为发布派生值。
3. **方向敏感。** 坡度按有向边保存；同一路段正反方向的爬升、下降和通行成本不同。
4. **来源与结论分离。** 原始来源、计算方法、人工审核和最终发布值分别记录。
5. **置信度参与路由。** 低置信度数据不能与现场或校方核实数据等价使用。
6. **稳定迁移。** 属性主库使用持久 `segment_id`，当前 `(u,v,key)` 只是某个路网版本的绑定。
7. **可复现。** 数据源版本、文件校验和、处理参数、方法版本和发布时间进入同一来源清单。
8. **开放与授权分层。** 开放数据、校方授权数据、商业在线结果和现场记录分别注明许可与可发布范围。

## 4. 文件与分层

### 4.1 来源清单

新增 `data/edge_attribute_sources.json`，记录：

- 来源 ID、名称、数据类型和版本；
- 获取日期、覆盖范围、坐标系统和分辨率；
- 原始文件校验和或在线服务请求批次；
- 许可、公开范围和再发布限制；
- 处理脚本与方法版本。

原始 DEM、遥感影像等大文件保存在受控缓存中，不直接写入 Git；来源清单保存其校验和和可重复获取信息。

### 4.2 属性主库

新增 `data/edge_attribute_master.json`。每个持久路段记录：

```json
{
  "segment_id": "seg_...",
  "network_bindings": [
    {
      "network_version": "...",
      "edge_id": [0, 0, 0],
      "source_refs": ["way/..."],
      "geometry_hash": "..."
    }
  ],
  "terrain": {},
  "scenery": {},
  "verification": {},
  "updated_at": "..."
}
```

### 4.3 审核记录

新增 `data/edge_attribute_review_decisions.json`，只保存人工、现场或校方审核决定，包含证据、审核人、时间、适用方向和替代值。自动脚本不得覆盖已经核实的决定。

### 4.4 发布快照

在加载层迁移完成前，继续生成兼容的 `data/road_annotations.json`，但它成为主库的派生产物。发布快照只包含运行时必需字段，同时附带 `terrain_confidence`、`scenery_confidence`、`method_version` 和 `verification_status`。

## 5. 坡度属性

### 5.1 字段

每条有向边保存：

- `elevation_start_m`、`elevation_end_m`；
- `grade_signed_pct`：沿行进方向的有符号平均坡度；
- `grade_abs_pct`；
- `grade_p90_pct` 或可用高程剖面的高分位坡度；
- `elevation_gain_m`、`elevation_loss_m`；
- `facility_type`：普通道路、坡道、台阶、电梯、扶梯、桥、隧道或室内通道；
- `slope_level`：派生的 1–5 级，可为空；
- `source_refs`、`method_version`、`confidence` 和 `verification_status`。

反向边使用同一高程剖面反向计算：平均坡度符号翻转，爬升与下降互换。台阶和无障碍属性作为设施事实独立保存，不能只靠数值坡度推断。

### 5.2 来源优先级

从高到低为：

1. 校方测绘、工程或授权高程数据；
2. 现场 GNSS、测量设备或经过质量控制的轨迹与气压高程；
3. 有明确版本和分辨率的离线地形 DEM；
4. OSM `incline`、`steps`、`ramp` 等结构化标签；
5. 连续同名道路或相邻已知路段的推断；
6. 旧占位等级，仅作为迁移候选，不进入正式可信值。

开放 DEM 需要下载为版本化输入再离线处理，不能只依赖无数据版本说明的在线聚合接口返回值。

### 5.3 计算规则

- 沿完整路段几何采样高程剖面，采样间距依据源分辨率确定，不只比较两个端点；
- 先处理垂直基准、空洞和异常值，再进行与分辨率相匹配的平滑；
- 路段长度不足以跨越足够 DEM 单元时，DEM 结果只能标为低置信度；
- 30 米级 DEM 对长度不足 90 米的路段不产生中、高置信度坡度结论；
- 共享节点的高程差必须通过连续性检查；
- 极端坡度与台阶、桥梁、隧道、建筑边界和 DEM 跳变交叉检查后进入人工审核队列；
- 分级阈值保留现有 `<2%、2–5%、5–8%、8–15%、≥15%` 作为初始发布规则，但连续值始终保留，阈值版本单独记录。

## 6. 景观属性

### 6.1 可解释特征

每条路段不直接填写单一“好看程度”，先保存 0–1 特征或 `null`：

- `greenery`：绿地、植被或树冠环境；
- `shade`：可推断的林荫或遮阳条件；
- `water`：湖泊、水岸和可见水体邻近度；
- `heritage`：历史建筑、校园文化地标和传统风貌；
- `quietness`：机动车道路等级、交通干扰和环境安静程度；
- `seasonality`：樱花、桂花、荷花、秋色等季节性；
- `viewpoint`：开敞空间、观景点或明确景观走廊；
- `scenery_score`、`scenery_level`、`confidence` 和 `verification_status`。

POI 邻近和道路名称只贡献某一项候选特征，不能直接决定最终等级。

### 6.2 来源

- OSM 的绿地、水体、自然、历史建筑、道路等级和步行设施；
- 校园 POI 主库中的景点、历史建筑和季节标签；
- 许可允许的植被或土地覆盖遥感产品；
- 校方授权的绿化、建筑和校园景观数据；
- 定向现场照片、路段核查与专家审核；
- 未来获得许可的机载影像派生特征。

商业地图的底图标注和照片只作线上核查线索，不能未经许可写入可再发布主库。

### 6.3 综合分数

首版透明公式为：

```text
scenery_score =
  0.25 × greenery +
  0.20 × shade +
  0.15 × water +
  0.15 × heritage +
  0.15 × quietness +
  0.10 × seasonality
```

`viewpoint` 作为有证据时的附加标记，不直接在缺少校准时重复加权。缺失特征不填 0；综合时只对已有特征重新归一化，并按有效特征覆盖率降低置信度。公式版本记为 `scenery_v1`，后续只有在代表性路段审核支持时才更新版本。

季节性特征按请求日期生效，基础绿地、水体和历史环境保持稳定。用户说“风景优先”时默认使用当前季节综合分；用户明确说“临湖、林荫、历史建筑”时允许使用对应子特征，而不是只使用总分。

## 7. 置信度与核实状态

### 7.1 置信度

- `high`：现场或校方核实，或分辨率足以支撑该路段且通过独立来源交叉验证；
- `medium`：版本化来源直接计算，尺度与路段长度匹配，并通过异常检查；
- `low`：邻近、名称、单一低分辨率来源或道路走廊继承推断；
- `unknown`：没有足够信息。

### 7.2 核实状态

- `source_only`；
- `derived_unverified`；
- `field_verified`；
- `institution_verified`；
- `rejected`。

置信度描述数据能支持多强的判断，核实状态描述证据经过了什么流程，两者不能合并成一个字段。

## 8. 路由使用规则

### 8.1 平坦优先

- 中、高置信度坡度进入正常成本；
- 低置信度和未知边承担不确定性惩罚，不能被当作平坦路；
- 明确台阶、禁止通行和无障碍限制继续作为硬约束；
- 路线中未知坡度长度占比超过 20% 时，响应标记 `terrain_quality_degraded`，不能声称路线已经验证为最平坦；
- “避开陡坡”与“无障碍”使用不同约束，后者对未知坡道和台阶采取更严格策略。

### 8.2 风景优先

- 中、高置信度综合景观分参与正常成本；
- 低置信度启发式只提供较弱增益，不能单独把路段提升为最高等级；
- 路线中有效景观特征覆盖长度低于 80% 时标记 `scenery_quality_degraded`；
- 当数据质量不足或推荐路线超过绕行上限时，自动降低景观偏好并说明原因；
- 路线解释只引用实际存在的特征，不生成“林荫、临湖、历史建筑”等未经数据支持的描述。

## 9. 路网重建与属性迁移

1. 为当前主库记录生成持久 `segment_id`；
2. 新路网优先按 OSM/source refs 匹配；
3. 再按方向、几何重合、端点邻近和长度差匹配；
4. 自动匹配结果保存匹配方法和置信度；
5. 一对多、多对一或几何变化大的路段进入人工迁移队列；
6. 只有通过发布门槛的匹配结果才能生成运行时快照；
7. 每次发布报告已匹配、低置信度、失配、新增和删除路段数量。

## 10. 生产流水线

### 10.1 根目录与输入治理

- 所有脚本统一使用 `Path(__file__).resolve().parents[2]` 定位项目根目录；
- 脚本支持显式输入和输出路径，默认只写候选或审计目录；
- 原始来源先缓存和登记校验和，正式主库不直接依赖临时在线响应；
- 生成流程不得覆盖人工审核决定。

### 10.2 阶段

1. `audit`：盘点当前占位、来源、等级分布和路网绑定；
2. `ingest`：登记 DEM、OSM、POI、遥感、校方或现场候选源；
3. `derive-terrain`：生成有向高程剖面和坡度候选；
4. `derive-scenery`：生成可解释景观特征；
5. `review`：输出异常、高影响和低置信度核查队列；
6. `publish`：合并审核决定并生成版本化运行时快照；
7. `validate`：验证结构、分布、路网绑定和代表性路线数据质量。

各阶段输入输出不可混用；自动候选不能跳过审核层直接成为现场结论。

## 11. 核查优先级

按路线影响而不是边数量排序：

1. 代表性 OD 和高频通勤走廊；
2. 珞珈山、樱顶、山路和长台阶；
3. 信息学部—文理学部连接小路、校门和跨学部连接；
4. 澄波门、玉兰2门等通行权限仍需确认的连接；
5. 风景优先可能选择的湖滨、樱花、历史建筑和环山路段；
6. DEM 极端值、坡度方向异常和景观高分孤岛；
7. 普通低影响道路。

## 12. 验收标准

### 12.1 数据结构

- 当前路网每条边均绑定一个主库记录或明确列入未绑定清单；
- 所有坡度和景观值都有结构化来源、方法版本、置信度和核实状态；
- `unknown` 被单独统计，不再混入 3 级；
- 人工审核决定可重复加载且不会被自动流程覆盖；
- 路网重建产生完整迁移报告。

### 12.2 坡度

- 正反方向的坡度符号、爬升和下降一致；
- 共享节点高程连续，异常跳变进入审核队列；
- 台阶、坡道、桥、隧道和室内连接不会仅凭 DEM 判定；
- 所有代表性 OD、高风险边和平坦优先候选路线报告已知、低置信度和未知长度占比；
- 未达到质量门槛的路线不宣称“已验证最平坦”。

### 12.3 景观

- 景观分布不再由默认 3 级主导；
- 每条高景观路段至少有一个可解释特征和来源证据；
- 季节性、绿地、水体、历史和安静程度可以分别查询；
- 代表性景观路线的解释与实际特征一致；
- 未达到 80% 有效特征覆盖的路线明确降级，不宣称“风景最佳”。

### 12.4 发布

- 运行时只加载与当前路网版本匹配的发布快照；
- 数据、脚本、参数和来源清单能够在相同输入上重建相同结果；
- 开放、授权和商业数据的使用边界清楚；
- 数据质量报告与论文实验使用同一版本指纹。

## 13. 与 Agent 研究就绪方案的关系

本主库是 `flat`、`scenery` 和画像推荐策略的前置依赖。

- `shortest` 和普通通勤可以在本主库完善前运行；
- `flat` 与 `scenery` 可以在开发期展示候选结果，但只有达到本设计的数据发布门槛后才能进入正式论文实验；
- 路线响应必须携带坡度与景观数据质量摘要；
- 正式实验冻结主库版本、路网版本、派生方法版本和审核记录版本。

## 14. 范围边界

本阶段建立数据架构、派生流程、审核队列、运行时加载和质量报告。全校园逐边现场测量、无人机采集和校方数据授权获取属于持续数据工作；它们通过来源清单和审核层接入，不改变主库结构。
