# 管理端影像上传反馈体验设计

日期：2026-10-04
状态：已确认方案 A，待实施

## 目标

修复管理端“选择影像后没有任何反应”的体验问题。用户选中文件后，页面必须立即确认选择结果、展示可用预览并明确下一步；只有视觉服务、影像文件和校园观察区域全部就绪时，才允许用户主动开始识别。

本次不改变后端上传接口、任务队列、识别模型、审核流程或道路事件发布规则。

## 用户流程

1. 用户在“机载影像巡查”中选择图片或短视频。
2. 页面立即显示文件名、格式化后的大小和媒体类型。
3. 图片使用浏览器本地对象 URL 显示缩略图；视频只显示文件摘要，不自动播放。
4. 页面根据当前状态只强调一个下一步：
   - 视觉服务未就绪：说明暂时不能识别，并保留已选文件信息；
   - 尚未选文件：提示选择图片或短视频；
   - 尚未标注区域：提示点击“标注影像所在校园区域”，再点击地图；
   - 三项就绪：显示“已准备好，可以开始识别”。
5. 主按钮文案改为“开始识别”，只有三项条件全部满足且没有正在上传时才可点击。
6. 上传成功后释放本地预览 URL、清空文件摘要，并提示任务已进入分析队列。
7. 用户重新选择文件、退出登录或上传结束时，旧预览资源必须被释放，避免浏览器内存持续占用。

## 界面结构

现有上传虚线框继续作为文件选择入口，不改变管理台整体布局。其下新增一个默认隐藏的媒体摘要区：

- 图片缩略图；
- 文件名；
- 文件大小与类型；
- “重新选择”提示由现有上传框承担，不新增多余按钮。

现有 `vision-message` 继续作为流程与错误提示区，避免同时出现多个竞争性提示。视觉状态条负责系统级状态，流程提示负责用户下一步，两者职责分离。

视觉样式沿用管理台现有深绿色、纸张色和金色状态线。缩略图以 `object-fit: contain` 完整展示，不裁剪影像；移动端保持单列，不引入弹窗。

## 状态与数据流

前端继续以以下状态作为唯一提交门槛：

- `state.inferenceReady`：服务器返回视觉推理已就绪；
- `media-file.files.length > 0`：浏览器已选择文件；
- `state.anchor`：用户已在校园地图标注观察区域；
- `!state.visionUploadBusy`：当前没有正在提交的任务。

文件选择事件负责：

1. 释放旧预览；
2. 校验客户端可提前判断的文件类型与大小；
3. 更新摘要和图片预览；
4. 更新流程提示；
5. 重算按钮状态。

地图标注、视觉状态轮询和上传结束也统一调用同一个流程提示更新函数，确保按钮状态与说明不会互相矛盾。

## 校验和错误处理

- 支持范围保持 JPG、PNG、WebP、MP4、MOV、AVI、WebM。
- 文件超过服务端返回的大小上限时，摘要仍显示，但明确标为不可提交，并提示当前上限。
- 浏览器没有提供可靠 MIME 类型时，允许使用受支持扩展名判断；最终仍由后端文件头校验兜底。
- 图片预览加载失败不阻止合法文件提交，但显示“无法生成本地预览，仍可尝试识别”。
- 视觉服务失联或未就绪时按钮保持禁用，提示用户等待服务恢复，不暗示文件正在上传。
- 真正的网络请求仍只在用户点击“开始识别”后发送。

## 无障碍与隐私

- 文件摘要与流程提示使用现有可感知状态区域，使屏幕阅读器能够读出选择结果。
- 缩略图使用描述性替代文本，不把文件路径暴露到页面。
- 本地预览只使用浏览器对象 URL，不把文件提前发送到服务器。
- 键盘用户继续通过与隐藏文件输入绑定的标签打开选择器，焦点样式保持可见。

## 测试与验收

JavaScript 自动化至少覆盖：

1. 选择合法图片后显示文件名、大小、缩略图，并提示标注区域；
2. 只选择文件时按钮仍禁用；
3. 标注区域且视觉服务就绪后按钮启用，提示可以开始识别；
4. 超限文件显示明确错误且按钮禁用；
5. 重新选择文件时释放旧对象 URL；
6. 上传成功和退出登录时清理摘要及预览；
7. 视觉状态轮询变化后，提示和按钮同步更新；
8. 现有防重复提交行为保持不变。

视觉验收包括桌面和窄屏两种宽度，检查图片不裁剪、长文件名可换行、状态文案不挤压按钮，并确认不影响道路事件管理流程。

## 不在本次范围

- 选择文件后自动上传；
- 拖拽上传、多文件批量上传或上传进度条；
- HEIC 转码；
- 修改模型类别、道路定位能力或识别准确率；
- 自动把视觉候选发布为道路事件；
- 线上服务器部署和生产管理员操作。
