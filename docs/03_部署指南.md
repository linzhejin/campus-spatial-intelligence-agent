## 首次部署（服务器上执行）

```bash
sudo apt update && sudo apt install -y python3 python3-venv python3-pip git
cd /home/ubuntu
git clone <gitee-repo-url> campus-spatial-intelligence-agent
cd campus-spatial-intelligence-agent
python3 -m venv venv
venv/bin/pip install --upgrade pip
venv/bin/pip install -r requirements.txt
```

也可直接运行仓库自带脚本（自动完成建虚拟环境、装依赖、写 systemd 单元并启动）：

```bash
bash deploy.sh
```

注意脚本模板生成的单元是 `--bind 0.0.0.0:5000`（监听全部网卡，需自行用安全组/防火墙拦住外网 5000）；Caddy 与应用同机时建议按下文收窄为 `--bind 127.0.0.1:5000`。

`.env` 不存在时 `deploy.sh` 会从 `.env.example` 复制并强制写入 `FLASK_ENV=production`；检测到占位符密钥会中止并提示先填密钥。

## 环境变量

推荐写入项目根目录 `.env`（`config.py` 用 python-dotenv 加载）。生产环境需将 `.env.example` 中的 `SECRET_KEY` 占位值替换为至少 32 个字符的随机密钥；应用启动时会拒绝缺失、占位或过短的生产密钥。

| 变量 | 必填 | 说明 |
|---|---|---|
| `DEEPSEEK_API_KEY` | 是 | DeepSeek API Key；`config.py` 内部将其同时赋给 `OPENAI_API_KEY` 变量供 OpenAI SDK 读取（环境变量本身只认 `DEEPSEEK_API_KEY`） |
| `OPENAI_BASE_URL` | 否 | 默认 `https://api.deepseek.com/v1` |
| `LLM_MODEL` | 否 | 默认 `deepseek-chat` |
| `AMAP_KEY` | 是 | 高德 JS API 2.0 Key（前端底图；天气 Web 服务在未设 `AMAP_WEB_KEY` 时也回退用它） |
| `AMAP_SECURITY_CODE` | 是 | 高德 JS API 2.0 安全密钥 |
| `AMAP_WEB_KEY` | 否 | 高德 Web 服务 Key（天气接口）；不设置则回退 `AMAP_KEY` |
| `SECRET_KEY` | 生产必填 | Flask session 密钥；生产必须配置至少 32 个字符的随机值，缺失或使用占位值时应用拒绝启动 |
| `ROAD_CONDITION_ADMIN_PASSWORD` | 路况写操作需要 | 网页管理员登录口令；不设置则 `POST /api/admin/login` 返回「管理员功能未配置」 |
| `ROAD_CONDITION_ADMIN_TOKEN` | 系统对接需要 | 外部系统（如保卫部）Bearer Token；不设置则只允许网页 session |
| `DATABASE_URL` | 新 Agent 会话必填 | PostgreSQL 连接串；启动时自动应用 `storage/migrations/*.sql`。未配置时，持久会话接口返回 503，不回退成假持久化 |
| `AGENT_WORKER_CONCURRENCY` | Agent 任务必填 | 后台任务并发 worker 数，默认 3，范围 1–16；需启动 `python -m jobs.worker` |
| `VISION_MODEL_PATH` | 机载影像分析 | 视觉 worker 所在主机上的本地模型文件路径；留空时管理台会明确显示模型未就绪，不会自动联网下载 |
| `VISION_MODEL_ID` / `VISION_MODEL_REVISION` | 影像识别审计 | 记录使用的模型名与固定版本/提交号；本项目固定为 `visdrone-rtdetrv4-s` / `820fca3d962243f7d611dd35cf2a64d267635499` |
| `VISION_CONFIDENCE_THRESHOLD` | 影像识别 | 车辆检测最低分数，默认 `0.369`（模型卡报告的 VisDrone F1 最优点）；校内结果仍需复核 |
| `VISION_CPU_THREADS` | 视觉 worker | ONNX Runtime CPU 线程数，默认 1，避免与 Agent 抢占小规格实例 |
| `VISION_UPLOAD_DIR` | 影像管理 | 私有上传目录，默认 `data/vision/uploads`；不要映射到静态文件目录 |
| `VISION_MAX_MEDIA_BYTES` | 影像管理 | 图片上传上限，默认 24 MiB |
| `VISION_MAX_VIDEO_BYTES` | 影像管理 | 分块视频上传上限，默认 1 GiB；续传中的临时数据也占用此目录所在磁盘 |
| `VISION_CHUNK_BYTES` | 影像管理 | 单个视频上传块大小，默认 8 MiB；反向代理允许略大于此值的请求体即可 |
| `VISION_MAX_FRAME_PIXELS` | 影像分析 | 单帧最大像素数，默认 12,500,000；超限媒体会拒绝分析，避免超大图像耗尽视觉 worker 内存 |
| `FLASK_ENV` | 是 | 生产固定 `production`（关 debug、限制 1MB 请求体、启用 CORS 白名单） |
| `CORS_ORIGINS` | 建议 | 逗号分隔的允许来源，生产一般填 `https://whuspati.online` |
| `MAP_CENTER_LAT` / `MAP_CENTER_LNG` / `MAP_ZOOM` | 否 | 地图中心与缩放，默认 30.5365 / 114.3630 / 16 |
| `WHU_BBOX_NORTH/SOUTH/EAST/WEST` | 否 | OSM 下载边界框，默认值见 `.env.example` |

### 持久 Agent 与后台进程

新对话入口将会话、任务版本、消息、澄清状态和运行事件写入 PostgreSQL。生产环境需先创建数据库与专用账号，并将 `DATABASE_URL` 配入 Web 和 worker 环境；应用会自动逐个执行版本化迁移。数据库不可用时接口明确报错，不会悄悄切换成仅保存在进程内的会话。

腾讯云单机部署可先安装本机 PostgreSQL，并创建仅供应用使用的账号和数据库：

```bash
sudo apt-get update
sudo apt-get install -y postgresql
sudo -u postgres createuser --pwprompt whu_walker
sudo -u postgres createdb --owner=whu_walker whu_walker
```

将 `DATABASE_URL=postgresql://whu_walker:<密码>@127.0.0.1:5432/whu_walker` 写入服务器 `.env`；若密码含 URL 保留字符，需进行百分号编码。不要将连接串提交到 Git。首次部署脚本会先连接数据库并执行迁移，连接失败就停止，不会把网页更新到缺少存储的状态。

Agent 执行与 Web 请求分离，需额外以同一虚拟环境、工作目录和数据库配置运行：

```bash
venv/bin/python -m jobs.worker
```

部署脚本会安装 `ops/systemd/whu-agent-worker.service` 并与 Web 一同启用。已有服务器若尚未创建此 unit，应先在项目根目录执行：

```bash
sed -e "s|@APP_DIR@|$(pwd)|g" -e "s|@APP_USER@|$(whoami)|g" \
  ops/systemd/whu-agent-worker.service \
  | sudo tee /etc/systemd/system/whu-agent-worker.service >/dev/null
sudo systemctl daemon-reload
sudo systemctl enable --now whu-agent-worker
sudo systemctl is-active whu-agent-worker
```

多实例 worker 通过数据库租约领取任务；每个 worker 有独立 LangGraph PostgreSQL 检查点，失去租约的过期结果不会覆盖新状态。Web 和 worker 都必须指向同一数据库。部署更新时一并重启 `whu-walker` 与 `whu-agent-worker`，并确认两个 unit 都为 `active`。管理员专用页面为 `/manager`，仍使用现有管理员口令或系统 Token；网页登录写操作需带会话 CSRF 令牌。

### 机载影像分析（可选服务）

按部署方式，将 `requirements-vision.txt` 装入 Web 共用的虚拟环境；视觉推理和 Web 请求仍在独立进程运行。视觉 worker 用 ONNX Runtime CPU 推理，不在云端安装 PyTorch/Ultralytics；模型文件单独放服务器目录，权重不提交到 Git。部署脚本只有在本地权重和视觉依赖齐全时才启用 `whu-vision-worker`；worker 实际加载并校验 ONNX 输入/输出后才报告就绪，管理台还会检查近期心跳，任一项未就绪都会禁用上传：

```bash
cd /home/ubuntu/campus-spatial-intelligence-agent
venv/bin/pip install -r requirements-vision.txt
# 先把固定版本的模型转换为 ONNX 并放入 /opt/whu-walker/models/
# VISION_MODEL_PATH=/opt/whu-walker/models/visdrone-rtdetrv4-s.onnx
# VISION_MODEL_REVISION=820fca3d962243f7d611dd35cf2a64d267635499
bash deploy.sh
sudo systemctl status whu-vision-worker
```

模型只在有足够内存的开发机上下载并导出，生产机只接收转换好的 ONNX 文件：

```bash
# 在项目开发机的临时工作目录固定检出导出代码
git clone https://github.com/dronefreak/RT-DETRv4.git /tmp/RT-DETRv4
git -C /tmp/RT-DETRv4 checkout be440e87ca85927404e739c2dee17c502cd09939
# 使用独立的导出环境，按该仓库 requirements.txt 安装 PyTorch 后再装导出依赖
python -m venv /tmp/vision-export
/tmp/vision-export/bin/pip install -r /tmp/RT-DETRv4/requirements.txt onnx onnxsim onnxscript
python scripts/vision/prepare_model.py --download-only
python scripts/vision/prepare_model.py --rtdetrv4-source /tmp/RT-DETRv4
sha256sum models/vision/visdrone-rtdetrv4-s.onnx
```

脚本锁定模型仓库提交号并验证 42,411,147 字节原始 checkpoint 的 SHA256；它会检查 ONNX 可独立加载、通过结构校验后才写入 manifest 和 SHA256。部署时只上传自包含的 `visdrone-rtdetrv4-s.onnx` 到服务器模型目录，不上传 `.pth`、数据集或导出环境。

目前使用的 VisDrone 航拍车辆模型按模型卡报告 11 类检测能力，不含事故类。单张图片只计数/标框，不判断拥堵；视频分析自动尝试估算镜头全局运动，补偿质量不足时仅展示车辆统计；只有足够帧数、车辆轨迹和低位移证据才生成拥堵候选。地图标注仅为观察区域，识别框不换算为地面坐标。当前版本明确不支持事故识别；取得许可清楚、具有事故标注的数据及专用模型后再扩展。任何候选都不会自动改变路网通行状态。

模型来源：`dronefreak/visdrone-rtdetrv4-s`（[模型卡](https://huggingface.co/dronefreak/visdrone-rtdetrv4-s)），输入边长 960，模型卡报告 VisDrone 测试集 mAP@50 46.28、car AP@50 82.49；这些值不能代替本项目在公开样本上的复现结果，更不能代表武大实际精度。该权重以 VisDrone 数据训练，数据集条款限制为非商业研究用途；本项目保留引用、版本与校验和，权重不随应用再分发。若用途变化，需重新核验数据和模型许可。

本机或服务器没有配置权重时，管理台禁用分析提交并解释原因；不能把“队列与页面已部署”当作“检测模型已经可用”。上传媒体目前没有自动保留期，部署者需在启用前制定符合审核留证需要的清理政策。

### 管理员鉴权双通道

写路况（POST/PATCH/DELETE `/api/road-conditions`、GET `/snap`）接受任一通道：

1. **网页 session**：`POST /api/admin/login`，请求体 `{"password": "..."}`，成功后写 session Cookie；另有 `GET /api/admin/status`、`POST /api/admin/logout`。
2. **系统对接 Token**：请求头 `X-Admin-Token: <token>`，或 `Authorization: Bearer <token>`；与 `ROAD_CONDITION_ADMIN_TOKEN` 常量时间比较（hmac.compare_digest）。事件 `created_by` 分别记录为 `web` / `token`。

curl 示例（服务器或本地均可）：

```bash
curl -X POST https://whuspati.online/api/road-conditions \
  -H "Content-Type: application/json" \
  -H "X-Admin-Token: $ROAD_CONDITION_ADMIN_TOKEN" \
  -d '{"type":"closure","name":"樱花大道封闭演练","lng":114.365,"lat":30.536}'
```

## systemd 服务

单元文件 `/etc/systemd/system/whu-walker.service`（`deploy.sh` 会自动生成，其中 bind 为 `0.0.0.0:5000`）。同机 Caddy 部署建议手工收窄为环回地址：

```ini
[Unit]
Description=WHU Walker (珞珈智行)
After=network.target

[Service]
User=ubuntu
WorkingDirectory=/home/ubuntu/campus-spatial-intelligence-agent
ExecStart=/home/ubuntu/campus-spatial-intelligence-agent/venv/bin/gunicorn app:app --workers 2 --threads 4 --timeout 60 --max-requests 1000 --bind 127.0.0.1:5000
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

线上即为此形态：gunicorn 只绑定 `127.0.0.1:5000`，公网暴露由 Caddy 负责，安全组仅放行 22/80/443。若沿用 `deploy.sh` 生成的 `0.0.0.0:5000`，必须确认云防火墙不放行 5000 端口。

### gunicorn 硬约束

- **必须**使用：`--workers 2 --threads 4 --timeout 60 --max-requests 1000`
  - `--timeout 60`：Agent 规划器自身预算 6 轮 / 40s，必须在 60s 内收尾
  - `--max-requests 1000`：worker 处理 1000 请求后自动重启，控制内存
- **禁止** `--preload`（多 worker 共享路网等全局对象会冲突）
- **禁止** `--keepalive`、`--max-requests-jitter`（现版本不识别，启动失败）

## Caddy 反向代理（HTTPS）

安装 Caddy 后编辑 `/etc/caddy/Caddyfile`：

```caddy
whuspati.online {
    reverse_proxy 127.0.0.1:5000
}
```

重载：`sudo systemctl reload caddy`。Caddy 自动向证书机构申请并续期证书，只需提前把域名 A 记录指向 152.136.102.172 并放行 80/443 端口。

## 路网预热与初始化

- `FLASK_ENV=production` 时，进程启动会开后台线程调用 `load_or_download_network()` 预热路网，失败只告警不影响启动。
- 缓存文件 `data/whu_road_network.graphml` 不入 git；缓存缺失时首次加载从 OSM 下载（服务器需装 `requirements-dev.txt` 中的 osmnx，或预先把 graphml 上传到 `data/`）。
- 强制重建：`venv/bin/python scripts/network/rebuild_network.py`；也可 `POST /api/network/init`（带 `{"force": true}` 强制重下）。

## APK 与静态资源

- APK 与版本清单位于仓库 `static/app/`（`whu-walker.apk`、`latest.json`），随发布覆盖更新，URL 保持不变。
- APK 客户端启动后拉 `https://whuspati.online/app/latest.json`，比较 `versionCode`，更高则弹窗、后台下载并做 SHA-256 校验后拉起系统安装器。
- Service Worker 对 `/app/*` 与 `/api/road-conditions*`、`/api/admin*` 一律 network-only，APK 和版本清单不会被缓存。

## 高德 Key 配置

在高德控制台为 `AMAP_KEY` 设置 JS API 2.0 域名白名单，至少包含 `whuspati.online`（生产域名），否则底图报 `INVALID_USER_KEY`；`AMAP_SECURITY_CODE` 必须与 Key 配套。
