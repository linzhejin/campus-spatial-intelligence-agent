## Files Created

### `scripts/validate_sla.py`
- SLA validation script with dual-mode operation:
  - **Online mode**: sends 15 queries x 3 rounds = 45 POST requests to `/api/chat`, records wall-clock latency, computes P50/P90/P99, checks for crashes/timeouts
  - **Offline mode**: component-based latency model using Monte Carlo triangular-distribution simulation (seed=42)
- Key design decisions:
  - Uses `urllib.request` (stdlib only, no external dependencies) for maximum portability
  - Timeout threshold: 60s per request
  - Measures wall-clock time via `time.perf_counter()`
  - Percentile calculation uses linear interpolation (same method as many APM tools)
  - Windows-compatible: all emoji removed, UTF-8 encoding forced via `io.TextIOWrapper` on win32
  - Supports `--url`, `--offline`, `--rounds`, `--output-json` CLI arguments

## Methodology Notes

### Online Mode
- 15 standard queries (from T-028) x 3 rounds
- POST to `/api/chat` with `{"query": "..."}` payload
- Wall-clock latency recorded per request
- >60s = timeout; connection errors = crash
- P50/P90/P99 computed from sorted latencies

### Offline Mode
- Component breakdown: LLM parse (2.5s) + route compute (0.3s) + LLM explain (2.5s) + overhead (0.2s)
- Triangular distribution sampling with configurable min/mode/max
- Cold start adds 20-30s OSM download penalty (triangular, mode 25s)
- Deterministic seed (42) for reproducibility

## Limitations

- Offline estimation may not reflect real LLM API latency variance
- Cold start estimate is conservative; actual OSM download may be faster
- No concurrent load testing (serial requests only)
- AC3 verification requires live server with 15+ consecutive real queries
