## §3 复审新发现 — Stage 3 TDD 注意事项（8 项）

> 以下 8 项均为修订版 PRD 引入或初审未覆盖的实现细节问题，**不阻塞 Stage 3 启动**，但需在 TDD 阶段明确，否则实现时反复返工。

### N1 · 场景3 算法不明确（中优先级）

- **位置**：PRD §4 场景3 + 场景3 V1 限制
- **问题**："若用户仅指定起点 + POI 类型，系统自动选取最近的符合 POI 作为终点" — "最近"未定义是路网距离还是直线距离；多候选时如何选择
- **Stage 3 建议**：TDD 中明确算法（如：路网距离最短 + POI 类型过滤 + 同距离时取 scenery_score 最高）

### N2 · 快捷按钮与默认权重协同矛盾（高优先级）

- **位置**：PRD §6 F-001 快捷按钮映射 + F-003 默认权重
- **问题**：快捷按钮"距离优先"设置 distance=short，但 F-003 默认权重 w_c > w_s > w_d（景观最高）。distance=short 修改约束等级但不修改权重，可能出现"用户选距离优先，但路线仍优先景观"的矛盾结果
- **Stage 3 建议**：TDD 中明确约束等级与权重的映射关系（如：约束等级触发权重偏移，distance=short 时 w_d 上调 + w_c/w_s 下调），具体偏移幅度可在 config.py 中参数化

### N3 · crowd（人流）维度缺失（中优先级）

- **位置**：PRD 附录A query 9 "从樱花大道到老斋舍，避开人流"
- **问题**：query 期望约束写 distance=relaxed，但"避开人流"语义上是 crowd 维度，与 distance 不同。当前 PRD 限定三类约束（distance/slope/scenery），可能无法精确表达此 query
- **Stage 3 建议**：TDD 中二选一 — (a) 将 crowd 映射为 distance=relaxed（简化方案，接受语义损失）；(b) 新增 crowd 维度（V1 不接实时人流数据，仅做"工作日 vs 周末 vs 樱花季"的时段近似）。建议 V1 用方案 (a)

### N4 · POI 数量下限 12 个的覆盖度（低优先级）

- **位置**：PRD §6 F-002 + §8 验收标准
- **问题**："至少 12 个 POI"是下限但非目标值。武大核心景点（樱花大道/樱顶/老图书馆/老斋舍/珞珈山/行政楼/教五/工学部/信息学部/梅园/桂园/牌坊/体育馆 等）合计可能远超 12 个；场景1-3 需要的 POI 是否被 12 个覆盖
- **Stage 3 建议**：TDD 中列出完整 POI 清单（建议 15-20 个），核对附录A 15 条 query 涉及的地名是否全部命中

### N5 · 附录C 标注覆盖率未量化（中优先级）

- **位置**：PRD 附录C "覆盖武大核心区主要路段"
- **问题**："主要路段"未量化；标注 20 条 vs 100 条对验收标准"重叠率 ≤ 70%"影响巨大
- **Stage 3 建议**：TDD 中明确标注范围（如：OSM 路网在武大核心区内的所有 highway=footway/path 的 80% 覆盖率），并列出标注清单

### N6 · F-003 降级触发条件不清晰（低优先级）

- **位置**：PRD §6 F-003 异常情况 "坡度/景观数据不可用 → 降级为仅距离成本"
- **问题**：手动标注完成后，理论上数据全可用。此降级在什么场景触发？是路网扩展到未标注区域？还是某条路段漏标？
- **Stage 3 建议**：TDD 中明确降级触发逻辑（如：路段缺标注 → 用邻近路段均值填充；邻域也无标注 → 降级为仅距离 + 在解释中标注"此路段缺标注数据"）

### N7 · F-008 指代理解验收测试集未定义（低优先级）

- **位置**：PRD §6 F-008 验收 "指代理解正确率 ≥ 80%"
- **问题**：未定义测试集大小、测试用例构造方式
- **Stage 3 建议**：TDD 中构造 10 条多轮对话测试集（含"换一条/更平坦/更短/换起点"等指代场景），80% 通过线对应 8/10

### N8 · PWA 验收缺乏技术指标（中优先级）

- **位置**：PRD §8 验收 "PWA 可添加到主屏幕"
- **问题**：仅功能验收，未规定离线缓存策略、Service Worker 要求、首屏资源大小等
- **Stage 3 建议**：TDD 中明确 — (a) manifest.json 配置；(b) Service Worker 缓存策略（首屏 HTML/JS/CSS cache-first）；(c) 离线降级显示；(d) 添加到主屏 icon 资源

### 初审结论：NEEDS_CHANGE

PRD 在需求边界和验收标准层面是自洽的，但四视角审核一致发现三个"不修改就必挂"的根本性矛盾：
1. **定位撕裂（CEO USER CHALLENGE）**：既说"轻松的个人 Demo"又按正式产品写 7 个 P0 功能，两头不占。
2. **验收 vs 数据的数学矛盾（ENG）**：重叠率 ≤ 70% 在坡度/景观双无数据的条件下，纯距离的推荐路线=最短路径，重叠率 = 100%，数学上无解。
3. **SLA vs 架构的 P95 超时（ENG）**：Render 冷启动 0–30s + 两次串行 LLM（P95 6–11s）+ 跨境 RTT，端到端 ≤ 15s 的 P95 几乎不可达。
4. **PRD 只有后端数据流，没有用户设计（DESIGN 平均 1.57/10）**：信息层级、缺失状态、响应式、可访问性、情感弧线全部空白。
5. **项目不可运行（DX 平均 1.0/10，TTHW 失败）**：缺 app.py/模块/前端，git clone 后无法启动，README 仅一行标题。

> 以上 5 项中的前 3 项已在复审中确认通过 PRD 修订 + 06_DECISIONS.md 决策充分解决。第 4–5 项属于 TDD/任务阶段的工作，PRD §10/§11 已补充可执行的设计规范框架与 DX 硬约束。
